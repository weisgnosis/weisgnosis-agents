# Library completion checklist

This is the single current checklist for completing weisgnosis-agents. The original promised library behavior remains the scope; WeisGnosis OS deployment and Temporal product tests are separate. Java API shapes, raw test counts and optional host platforms do not define completion.

The [parity reference](test-parity.md) retains upstream assertions and intentional differences. Its historical checklists are reference material, not a second delivery backlog. Reconcile substantive missing promised behavior with an outcome below; do not silently waive it or add an indefinite audit target.

### T: OpenTelemetry tracing adapter

This is required delivery with optional installation. Core/harness consumers must not acquire telemetry dependencies or exporters automatically. Start with a separate weisgnosis-agents-otel module depending on core and a compatible ZIO tracing API. [Official ZIO Telemetry guidance](https://zio.dev/zio-telemetry/opentelemetry/) is the dependency/API starting point; pin a version after compatibility inspection. Use fiber-aware context rather than Java ThreadLocal activation across asynchronous effects.

- [x] **T1: Explicit installation and ownership.** Borrow host-supplied tracing/context services. No constructor starts an SDK/exporter, registers globals or discovers environment settings. The host owns SDK/exporters, batching, flush and shutdown. Check Scala/ZIO dependency compatibility; update build aggregation, archive admission and external consumption for the optional artifact without CI expansion. Acceptance: core-only consumption has no telemetry dependency; an opt-in consumer installs tracing without ambient globals and agent cleanup does not close its borrowed SDK.
- [x] **T2: Invocation, reasoning and model spans.** Reuse PhaseObserver/PhaseCompletion and actual phase scopes. Activate fiber context for observed work, restore it on exit and end spans after owned work/request cleanup. Use stable span names and explicit correlation; distinguish fallback target calls. Reuse TurnCompletionObserver for authoritative AgentRunState attributes: a successful ZIO exit does not imply Completed, and Suspended/Interrupted/Stopped remain distinct from failures and caller delivery. Resumed invocations get new execution spans with explicit correlation, not invented continuity across restarts. Acceptance: an in-memory exporter sees correct nesting/boundaries, concurrent-context isolation and unchanged runtime success/failure/cancellation.
- [x] **T3: Accurate local-dispatch spans.** Add one scoped observation boundary around the existing typed Toolkit execution/normalization path, with ignore defaults, immutable invocation/ordinal and normalized result state or interruption cause. Preserve existential input/output types without casts. Measure dispatch separately from authorization/persistence. LocalToolResultObserver is too late to time dispatch; event subscribers do not own its lifecycle. Acceptance: success, normalized Error, encoding failure and cancellation have correct outcomes; repeated IDs remain distinct by occurrence; denied/supplied/external/provider-inline results are not executed local-tool spans.
- [x] **T4: Context, privacy and failure isolation.** Specify child inheritance, parallel sibling spans and explicit parent/link semantics for promoted tasks. Default attributes exclude prompts/thinking, arguments/results, credentials, endpoint queries and raw exception messages/stacks. Bound attribute/event counts and sizes; IDs are not metric labels and token deltas do not flood spans. Diagnose telemetry failures separately without replacing an agent result, inducing retries or swallowing interruption. The adapter performs no direct export/flush and creates no unbounded diagnostic queue. Supported production configuration requires a bounded asynchronous processor and nonblocking span completion; a host-selected synchronous processor can export during span.end and extend finalizer latency. Flush/shutdown remain host-owned. Remote propagation and JVM auto-instrumentation are not implicit.
- [x] **T5: Public tracing integration and review.** Exercise actual ReAct/model/tool execution using an in-memory SDK/exporter, including held cleanup, mixed failure, redaction and telemetry failure. Provide a host-owned SDK/export recipe and verify local OTLP export independently of provider correctness. Package/consume the optional adapter externally. Independent FP/ZIO and invariant reviews cover the final dispatch seam, context restoration and shutdown. Metrics/log bridges and collector hosting remain outside this tracing increment.

Primary surfaces: [PhaseObserver](../../modules/core/src/main/scala/com/weisgnosis/agents/core/agent/PhaseObserver.scala), [Toolkit](../../modules/core/src/main/scala/com/weisgnosis/agents/core/tool/Toolkit.scala), [ToolInvocation](../../modules/core/src/main/scala/com/weisgnosis/agents/core/tool/ToolInvocation.scala) and the optional adapter. Existing fail-closed observer contracts remain intact; this adapter deliberately isolates its operational telemetry failures. A post-persistence observer is not a tool timer.
