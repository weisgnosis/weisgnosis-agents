# Build definition support

[build.properties](build.properties) pins sbt; [plugins.sbt](plugins.sbt) declares build plugins, including scalafmt. Module dependencies and compiler options live in [build.sbt](../build.sbt). Run `sbt scalafmtAll scalafmtSbt` and `sbt verify packageArtifacts` after build or packaging changes.

The harness alone depends on SnakeYAML Engine 3.1.1 for bounded declaration event parsing; core and MCP do not gain a YAML dependency. Public parse events are read inside ZIO, without object loading. The [parser acceptance](../modules/harness/src/main/scala/com/weisgnosis/agents/harness/subagent/README.md#inline-declaration-parsing) retains its parser/dependency approval; current build identity is recorded below.

MCP tests run in a forked JVM so the standard java.class.path contains their actual runtime dependencies. The stdio integration suite uses that classpath and the same JDK to start its test-only peer; production code has no test-launcher dependency. The [transport acceptance](../modules/mcp/src/main/scala/com/weisgnosis/agents/mcp/transport/README.md#verification-and-acceptance) records review of this build setting.

MCP interoperability tests pin Java SDK `mcp-core`/`mcp-json-jackson2` 0.17.2, embedded Tomcat 11.0.18 and `slf4j-jdk14` 2.0.16 in Test scope only. The forked test JVM opens `java.base/java.lang` and `java.rmi/sun.rmi.transport` for Tomcat leak checks; JDK logging keeps server diagnostics visible. Production dependencies are unchanged. The [interop acceptance](../modules/mcp/src/main/scala/com/weisgnosis/agents/mcp/transport/README.md#independent-server-interoperability) records the fixture and test-configuration scope; current build identity is recorded below.

## Local artifact packaging

`packageArtifacts` invokes twelve standard sbt tasks: binary JAR, source JAR and Maven POM generation for core, harness, MCP and storage-postgresql. Outputs remain under each module's `target/scala-3.9.0`; the alias does not publish or install them. Both archive types include exactly one `META-INF/LICENSE` copied from the repository license. The root aggregate and the additional examples project are not published. Examples depends only on the three library Compile configurations and its own ZIO Test dependencies; it does not inherit MCP Java server fixtures. Root verify compiles and tests examples, while packageArtifacts includes four library distributions; examples remains unpublished and does not depend on the optional storage artifact.

Coordinates are `com.weisgnosis:weisgnosis-agents-{core,harness,mcp,storage-postgresql}_3:0.1.0-SNAPSHOT`. Harness and MCP depend on the packaged core artifact; optional storage-postgresql depends on packaged harness. PostgreSQL JDBC 42.7.11 remains Test-only, and production driver/pool ownership stays with the host; SnakeYAML Engine is a harness dependency only. Java SDK/Jackson, Tomcat, SLF4J and ZIO test dependencies retain Test scope and do not enter the consumer runtime. No repository remote is configured, and no SCM URL is invented in the POMs.

[CI](../.github/workflows/ci.yml) invokes `sbt verify packageArtifacts`. After packaging, it runs the [tracked artifact inspection and external consumer](../verification/artifact-consumer/README.md), including standalone formatting, representative public extension contracts, actual resolved module hashes and runtime classpath boundaries. No remote workflow execution or publication is established by local verification.

## Compatibility policy

All four library distributions remain development SNAPSHOT artifacts. No previously published binary-compatibility baseline or blanket API freeze is established. Defaulted additions can preserve ordinary source construction while changing positional extractors, Product arity, constructor method values and JVM signatures; downstream code must follow package migration contracts and rebuild dependent binaries.

Current public contracts include the documented core models/runtime/extension ports, harness policies/storage adapters, and MCP protocol/client/transport APIs. Package-private implementation helpers remain outside that host surface. The examples project and verification fixture are unpublished integration aids. Naming a public API here records its current accessibility and contract, not a promise that every signature is frozen for an RC.

The [client migration](../modules/core/src/main/scala/com/weisgnosis/agents/core/client/README.md#optional-reasoning-effort) records the current fifteen-field LlmConfig shape. The [eight-field ToolDef migration](../modules/core/src/main/scala/com/weisgnosis/agents/core/tool/README.md#provider-tool-schema-strictness) records optional per-tool provider strictness. The [tool result migration](../modules/core/src/main/scala/com/weisgnosis/agents/core/tool/README.md#typed-execution-observations) distinguishes supported String construction from changed ToolExecutionResult payload/state JSON and generated extractors. The [Toolkit migration](../modules/core/src/main/scala/com/weisgnosis/agents/core/tool/README.md#checked-registry-identity) removes unchecked Map/copy/Product reconstruction and preserves name-based checked registration. Persisted payload/checkpoint migration is distinct from recompiling host source; read the relevant package contract before upgrading.
