MemoryFlushManager supplies daily extraction through an injected DailyMemoryStore and can be installed as the compactor flush callback. LocalDailyMemoryStore supplies a scoped backend for host-controlled workspaces with exclusive cooperative ownership and atomic daily replacement. MemoryConsolidator enforces its counter budget before an atomic content/progress commit; MemoryRepository.inMemory implements shared daily/consolidation authority. LocalMemoryRepository supplies the daily/consolidation ports with shared ownership and journal recovery before each operation. Transcript recording can be installed through TurnCompletionObserver with an explicit anonymous-message policy. Completion-triggered flush scheduling is available through MemoryFlushScheduler. MemoryConsolidationScheduler adds opt-in owner-coalesced background consolidation with explicit result reporting. Explicit acknowledged-daily archival is available through MemoryRepository.retention. Explicit selected-target transcript pruning and configured maintenance are available; session discovery, remote memory/transcript storage, general middleware and durable workflow storage remain pending. Hosts choose a memory store and supply summarization/offload effects and authenticated approval routing.

Local storage requires WorkspaceTrust.HostControlled and protected filesystem ancestors. Tool-result publication requires hard-link support; memory/transcript publication requires atomic-move support. It is not a sandbox for untrusted workspaces. See [implementation notes](../../docs/architecture/phase-4-implementation.md) and the [tracker](../../docs/architecture/tracker.md).

Configured factories filter both inherited and automatically registered tools before client/runtime construction, preserve the supplied authorizer and retain resources in the caller or supervised worker Scope. The opt-in inherited-denial wrapper reads current parent policy before child authorization and against approved arguments, while preserving the child policy. The scoped registry bounds retained record count, keeps full Exit results, and joins attached/promoted task cleanup at registry closure. Opt-in spawn/task/cancel tools retain the fixed registry authority; forSession supplies send/task/cancel for one host-selected session with no session_id input. The inherited plan gate samples parent and child modes and applies existing strict admission if either is Plan; it changes no approval state. External parent permission gates, atomic approval revocation, declaration loading, automatic named reusable-session creation and durable reuse remain outside these contracts. `TaskSupervisor.own` retains resources beyond initialization and completed turns, joins nested workers before resource finalizers, and shares the complete cleanup outcome across competing closers. Custom supervisors must implement this new abstract method. `SubagentSession.open` uses that ownership to retain one configured runtime/history and lineage. Its host-facing send serializes turns with separate execution IDs and current injected authorization; it promises no FIFO ordering. Trusted hosts control session, resource and spawner/factory capabilities. `SubagentSessionDirectory` supplies bounded host registration and lookup of acquired sessions, with joined removal/shutdown and unchanged original lifetime bounds. `SubagentTools.forDirectory` routes send/task/cancel through registered session IDs while preserving the same bounded observations and scoped execution. `SubagentConstruction` supplies an opt-in factory path carrying static boundaries and live ancestor Deny/Plan checks into nested children while preserving their confirmation authority. SubagentDeclaration adds checked inline configuration and an explicit general-purpose preset over this construction path; a scoped named factory catalog routes fresh-child spawn/task/cancel. Declaration loading and automatic named reusable-session creation remain pending.

Approval covers recorded revisions and named contracts. Remaining host integration and parity work stays visible in the [tracker](../../docs/architecture/tracker.md).
