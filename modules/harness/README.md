# weisgnosis-agents-harness

Context, persistence, permission and subagent components built on core. The host supplies model clients, storage, authentication and durable orchestration; scopes own local resources and explicitly promoted work.

Local artifact: `com.weisgnosis:weisgnosis-agents-harness_3:0.1.0-SNAPSHOT`. See the [packaging contract](../../project/README.md#local-artifact-packaging) for verified local consumption and publication limits.

The [subagent contract](src/main/scala/com/weisgnosis/agents/harness/subagent/README.md) defines invocation identity, installed child policies, checkpoints, durable task observations, cancellation, notifications, heartbeats and host-authorized recovery. [Storage contracts](src/main/scala/com/weisgnosis/agents/harness/storage/README.md) define conditional publication and explicit ownership; observations never restore executable sessions or confer execution authority. [Skill contracts](src/main/scala/com/weisgnosis/agents/harness/skill/README.md) define framing, loading and trust. Each package records its exact reviewed scope and verification; the [tracker](../../docs/architecture/tracker.md) retains unfinished original-plan obligations.

MemoryFlushManager supplies daily extraction through an injected DailyMemoryStore and can be installed as the compactor flush callback. LocalDailyMemoryStore supplies a scoped backend for host-controlled workspaces with exclusive cooperative ownership and atomic daily replacement. MemoryConsolidator enforces its counter budget before an atomic content/progress commit; MemoryRepository.inMemory implements shared daily/consolidation authority. LocalMemoryRepository supplies the daily/consolidation ports with shared ownership and journal recovery before normal operations. Explicit legacy-watermark migration instead refuses any journal and preserves all daily inputs as unacknowledged; both independent reviews and required verification passed. Transcript recording can be installed through TurnCompletionObserver with an explicit anonymous-message policy. Completion-triggered flush scheduling is available through MemoryFlushScheduler. MemoryConsolidationScheduler adds opt-in owner-coalesced background consolidation with explicit result reporting. Explicit acknowledged-daily archival is available through MemoryRepository.retention. Explicit selected-target pruning, bounded local transcript discovery and configured maintenance are available; remaining transcript discovery/pruning/layout migration and checkpoint runtime/host installation, segmented memory layouts/migration, general middleware and durable workflow storage remain pending. Hosts choose a memory store and supply summarization/offload effects and authenticated approval routing.

Local storage requires WorkspaceTrust.HostControlled and protected filesystem ancestors. Tool-result publication requires hard-link support; memory/transcript publication requires atomic-move support. It is not a sandbox for untrusted workspaces. See [implementation notes](../../docs/architecture/phase-4-implementation.md) and the [tracker](../../docs/architecture/tracker.md).
