## Pinned upstream adaptation

The source comparison uses `agentscope-java` revision `f98a685fdc4589f81e626e1686ac2c63d14a2304`. Static-boundary methods are in `agentscope-harness/src/test/java/io/agentscope/harness/agent/ManagedSubagentBoundaryTest.java`; permission methods are in `agentscope-harness/src/test/java/io/agentscope/harness/agent/tool/AgentSpawnToolPermissionTest.java`.

| Upstream method | Scala evidence and intentional boundary |
| --- | --- |
| `declarationFiltersAutoRegisteredToolsAsWellAsInheritedTools` | Factory final-filter scenario checks both inherited and construction-registered tools through the actual child's model input and attempts to dispatch `write_file`, verifying zero executions when excluded and one execution when allowed. Registration callbacks replace Java filesystem/builder wiring; this factory scenario does not test parsing or filesystem auto-installation; parser evidence is separate. |
| `childCannotReenableParentDeniedTool` | The same scenario verifies a child selecting a parent-denied inherited or construction-registered tool sees an empty toolkit; parent allowlist intersection and derived factories extend monotonicity coverage. Attempted excluded `write_file` dispatch produces an Error observation without execution. This is exact-name static capability narrowing, not dynamic permission inheritance. |
| `harnessChildReceivesParentDenyInActualExecutionSlot` | Actual configured-child runs install the inherited-denial wrapper and attempt an argument-matched denied call, yielding Denied without execution. Permitted near-misses still execute. Java harness/session wiring and permission-mode parity are excluded. |
| `directReactChildKeepsItsOwnPermissionContextAndAddsOnlyParentDeny` | Actual child runs preserve their own Allow, Ask and Deny behavior and confirmation policy while parent non-Deny decisions abstain. Live policy and confirmed-input rechecks extend the bounded adaptation; parent modes and working-directory inheritance are not implemented. |

These bounded adaptations are reviewed and verified at the recorded source identities. `declarationCanDisableParentDenyInheritance` is intentionally excluded from the safe declaration path: declaration data cannot disable ancestor Deny inheritance. Raw host factories remain separately trusted capabilities. `persistentReuseAndAgentSendAddCurrentParentDenyWithoutDuplicates` remains pending: sessions retain current installed policy and support model-facing send, but automatic Java-style context wiring and historical denial accumulation are not implemented. No complete upstream permissions-suite or model-facing spawn/send parity is claimed.

`AgentSpawnToolPromotionTest.innerTimeoutPromotesToAdoptedTaskRunSpec` has supporting tool-level evidence for a retained task ID, one continuing execution and later inspection/cancellation. The default Scala policy uses a fixed 30-second budget and the existing supervisor/registry; explicit checked synchronous waiting is described in the [host execution policy](../../../../../../../main/scala/com/weisgnosis/agents/harness/subagent/README.md#host-execution-policy). Java external repository adoption is not implemented. `AgentSpawnToolOrphanCancelTest.orphanAgentInterruptedOnParentCancel` has a scoped ownership adaptation: cancelling the actual spawn invocation joins child cleanup without detaching a continuing worker. Correlated child event forwarding remains outside these tests. These original gate/construction scenarios are separate from the reviewed child Plan installation evidence above. Live ancestor/child Plan OR deliberately replaces Java mode mutation, and live denial replacement does not implement historical accumulation.

`AgentSpawnToolForceSyncTest.helpers`, `zeroTimeoutCoercedToSync` and `timeoutHardFailsWithoutPromotion` have bounded typed-policy adaptations: checked host budgets, actual spawn/send completion, and timeout Error without a task ID or promotion after joined cleanup. The runtime table also preserves caller interruption and exact cleanup defects at admission. Java ambient Boolean/string coercion, model timeout_seconds=0, invalid-value fallback/clamping and absence of a separate background-repository record are intentional differences; Scala retains every execution in its existing registry.
