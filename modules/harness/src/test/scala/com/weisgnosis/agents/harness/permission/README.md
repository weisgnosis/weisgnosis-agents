# Permission verification

The [checkpoint-event scope](../../../../../../../main/scala/com/weisgnosis/agents/harness/permission/README.md#checkpoint-permission-events) is accepted. It extends existing ordinal/restore/input tables and adds one joined phase-drain group; generic event correlation does not establish human-source or durable-delivery authority.

[CheckpointPermissionAuthorizerSpec](CheckpointPermissionAuthorizerSpec.scala) adds two policy/lifecycle groups and [CheckpointPermissionIntegrationSpec](CheckpointPermissionIntegrationSpec.scala) adds one actual Ask/Allow table. They verify returned original-input pending data, host-fixed preparation, restored confirmation without repeated reasoning and no approval/stop events for Allow. [Final acceptance](../../../../../../../main/scala/com/weisgnosis/agents/harness/permission/README.md#nonblocking-checkpoint-policy) records both reviews, exact identities and verification.

Partial-confirmation tests have final independent approval and full verification. The [current contract](../../../../../../../main/scala/com/weisgnosis/agents/harness/permission/README.md#partial-checkpoint-confirmations) covers checked ordinal-position ledgers, successive restored subsets, preserved inline/completed processing, saved activation and Stop state, structured rejection and joined cancellation.

ConfirmedBatchAuthorizerSpec covers four grouped authorization contracts that exercise restored repeated-ID batches, modified/fixed/signed input and live policy/gate denial, complete-set and request identity rejection, and cancellation with joined failing gate cleanup. The existing rejection group also proves supplied ordinals require no confirmation, extra confirmations reject and replay attempts cannot reach policy. An additional accepted resumed-stream table verifies custom/default denial history, exact ordered Start/Delta/End context and no dispatch with one follow-up model request. Exact final scope and verification are recorded in the [batch contract](../../../../../../../main/scala/com/weisgnosis/agents/harness/permission/README.md#complete-batch-checkpoint-confirmations).

- [PermissionGateSpec](PermissionGateSpec.scala): priority combinations, restricted arguments, defaults, suspended callbacks, separately scoped sequential composition and failure/cancellation cleanup.
- [PermissionPromiseSpec](PermissionPromiseSpec.scala): registration before publication, one-shot resolution, duplicate requests, cancellation, and late responses.
- [DurableResumeSpec](DurableResumeSpec.scala): serializable values and immutable policy resumption only; no durable ReAct workflow is implied.
- [InteractivePermissionAuthorizerSpec](InteractivePermissionAuthorizerSpec.scala): ten adapter scenarios covering direct decisions, immediate confirmation, both modified-input gates, resource cleanup, concurrent rule additions, latest deny policy, declines, cancellation, typed failure, publication defects, and composed views retaining original authority and shared rules.
- [InteractivePermissionIntegrationSpec](InteractivePermissionIntegrationSpec.scala): six runtime scenarios covering same-phase modified execution, exact denial event order/identity/text/state, parallel repeated IDs, cancellation with completed siblings, policy lifetime, and independently confirmed rules surviving a later signed-input denial.

The three composition additions reuse the existing priority and authorization coverage: optional votes with ordered release, typed/defect/interrupted cleanup that skips later evaluation, and an added-gate view using the same confirmation authority with modified-input denial.
