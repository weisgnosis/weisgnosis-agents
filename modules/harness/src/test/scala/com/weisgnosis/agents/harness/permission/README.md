# Permission verification

The [permission contract](../../../../../../../main/scala/com/weisgnosis/agents/harness/permission/README.md) describes interactive waiting, explicit unavailable-channel denial, checkpoint admission and confirmation. Fresh invocation correlation is separate from the saved reply/request and call occurrence that authorize a restored confirmation; see [invocation identity](../../../../../../../../../core/src/main/scala/com/weisgnosis/agents/core/agent/README.md#invocation-identity-and-prepared-execution). Toolkit construction follows the [checked registry migration](../../../../../../../../../core/src/main/scala/com/weisgnosis/agents/core/tool/README.md#checked-registry-identity).

- [PermissionModeSpec](PermissionModeSpec.scala): explicit mode fallback, independent vote priority and admitted access restrictions; checkpoint and child-construction suites exercise current-policy integration.
- [PermissionAdvisorySpec](PermissionAdvisorySpec.scala): immutable suggestions remain presentation data, explicit confirmation controls rule installation, saved requests preserve occurrence identity, and provider failure/cancellation joins cleanup before any waiter is registered.
- [PermissionGateSpec](PermissionGateSpec.scala): priority, restricted arguments, defaults, suspended callbacks, ordered separately scoped composition and typed/defect/interrupted cleanup that prevents later evaluation. Affirmative Allow can resolve implicit Ask; composition is not restriction-only authority.
- [PermissionPromiseSpec](PermissionPromiseSpec.scala): registration before publication, one-shot resolution, duplicate requests, interruption and late responses.
- [DurableResumeSpec](DurableResumeSpec.scala): serializable confirmation values and immutable policy resumption; these alone do not establish a durable ReAct workflow.
- [InteractivePermissionAuthorizerSpec](InteractivePermissionAuthorizerSpec.scala): direct decisions, immediate confirmation, modified-input gate rechecks, joined cleanup, latest shared policy, declines, publication defects and composed views retaining confirmation authority and shared rules.
- [InteractivePermissionIntegrationSpec](InteractivePermissionIntegrationSpec.scala): same-phase execution, exact denied event identity/text/state, parallel repeated IDs, cancellation preserving completed siblings, policy lifetime and confirmed rules surviving later signed-input denial. Initial monotonic policy-denial/preparation observations precede Ask; dynamic gates remain at execution-time authorization, preserving plan_enter/plan_exit behavior.
- [CheckpointPermissionAuthorizerSpec](CheckpointPermissionAuthorizerSpec.scala) and [CheckpointPermissionIntegrationSpec](CheckpointPermissionIntegrationSpec.scala): nonblocking Ask/Allow, authoritative prepared input/access, live policy after gate cleanup, joined cancellation, original-input pending data and confirmed restoration without repeated reasoning. Allow emits no approval/stop events.
- [ConfirmedBatchAuthorizerSpec](ConfirmedBatchAuthorizerSpec.scala): complete repeated-ID batches, modified/fixed/signed input, current policy/gate denial, exact saved request/occurrence binding and cancellation with joined failing cleanup. Supplied ordinals need no confirmation; extra confirmations and replay attempts fail before policy. Resumed-stream checks retain custom/default denial history, ordered original-context Start/Delta/End, no denied dispatch and the subsequent model request.
- [PartialConfirmationSpec](PartialConfirmationSpec.scala): checked ordinal-position ledgers, successive restored subsets, preserved inline/completed processing, saved activation and Stop state, structured deferral rejection and joined cancellation. The phase-drain checks cover denied-before-Ask-before-Stop ordering, failure/cancellation suppression and supplied-result bypass; the [event-order oracle](../../../../../../../main/scala/com/weisgnosis/agents/harness/permission/README.md#checkpoint-event-order-oracle) requires exact phases, call IDs and terminal counts.
- [UnavailablePermissionAuthorizerSpec](UnavailablePermissionAuthorizerSpec.scala): unresolved-channel denial, affirmative Allow, independent Deny priority, prepared input/access, cold construction and policy sampling after joined gate cleanup.

[PlanPermissionIntegrationSpec](../plan/PlanPermissionIntegrationSpec.scala) checks admitted-access forwarding through both composition positions and confirmed-input rechecks. [SubagentConstructionSpec](../subagent/SubagentConstructionSpec.scala) exercises inherited policy in nested/reused runtimes and actual unavailable-channel denial without tool execution or suspension, with an allowed Build mutation and denied inherited Plan control.

Run `sbt "harness / test"` or repository-wide `sbt verify`. Generic checkpoint events provide correlation, not authenticated human-source or durable-delivery authority. Remaining event mappings, authenticated transport and durable host persistence remain visible in the [parity audit](../../../../../../../../../../docs/architecture/test-parity.md); these suites do not establish exhaustive upstream permission parity.
