# Verified sequential procedures

`ProcedureSession.open` binds a finite host-defined stage sequence to one `VersionedJsonStore` address and an explicit `Authority`. The host acquires an exclusive claim for that exact address in `Authority.acquire` and keeps it valid through scoped cleanup. CAS detects publication conflicts; it does not fence external execution or authenticate a caller. Stage and verifier functions are current constructor bindings, never decoded executable data. Change the explicit definition revision whenever their semantics change.

Each `advance` performs one stage attempt or verifies a saved submission. `run` continues until completion, exhaustion, or recovery is required. The session saves execution admission and its budget before invoking the executor, saves the exact submission before invoking its verifier, and saves acceptance before entering the successor. Only accepted submissions become the next stage's input. Rejection consumes an attempt; feedback is retained in the snapshot. Execution and verification admission counters survive reopen.

Reopening checks the exact ordered stage IDs, definition revision, attempts, limits and original input. Accepted stages are skipped. A saved submission resumes verification without rerunning the executor. Verifiers must be safe to repeat: interruption or lost acknowledgement may leave their result unpublished. An execution admission without a submission returns `RecoveryRequired`; this version supplies no replay, compensation, takeover or automatic mid-agent resume. The host must reconcile ambiguous external effects before choosing a new procedure run.

Every conflict or failed/interrupted persistence attempt blocks the current instance. Explicit reopen can observe an acknowledged or uncertain commit; it cannot prove whether an external action happened. The complete aggregate, individual JSON payloads, number of stages, per-stage attempts and aggregate execution/verification admissions are bounded. One persisted absolute deadline includes time offline and is checked across all attempts; the host supplies a trustworthy clock. Cancellation and deadline expiry join owned stage/verifier cleanup, which may take longer than the deadline. Full failure causes remain failures.

Payloads require valid Unicode, unique object keys, at most 64 nested container levels and 65,536 JSON nodes. Stored aggregates are checked before decoding with an 80-level and 4,194,304-node ceiling. Byte limits use exact JSON decimal rendering, including escaping and field names.

Run `sbt "examples/runMain com.weisgnosis.agents.examples.OfflineProcedure"` for an offline example that closes and reopens the actual local backend between two accepted stages. Local atomic replacement provides visibility without fsync or a power-loss recovery guarantee. This package adds no graph engine, scheduler, distributed execution fence, exactly-once effects, or transaction spanning the store and external services.
