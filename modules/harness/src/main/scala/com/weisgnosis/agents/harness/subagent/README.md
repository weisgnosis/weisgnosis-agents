# Scoped child execution and sessions

## Persistent named sessions

[SubagentNamedSessions.open](SubagentNamedSessions.scala) owns a bounded set of reusable child sessions selected by exact `(parentSessionId, agentId, label)`. The host supplies fixed current `SubagentEntry` factories, a borrowed [SubagentNamedSessionStore](SubagentNamedSessionStore.scala) and an `Authority` that acquires an exclusive claim for the exact registration/address. The claim must remain valid until runtime cleanup finishes. CAS detects conflicting persistence; it is not an execution fence or authentication mechanism.

`getOrOpen` shares one Promise per key and performs acquisition outside the short membership transition. Other keys can initialize independently. A waiting caller can cancel its wait without cancelling the initializer. Cancelled or failed initialization joins owned runtime/claim cleanup, resolves the shared Promise with its cause and retains a bounded failed slot. `retire` explicitly removes a failed slot, or joins an existing runtime before allowing a later generation. Callbacks must not close their own resource owner.

The strict version-1 envelope contains the checked registration and one `AgentSnapshot`: `Idle(history)` or `Suspended(AgentResult)`. It contains no live task, factory, policy or claim. Reopening acquires the current host claim first, loads bounded data and creates a fresh runtime through the supplied factory. Suspended restoration validates the checkpoint/current tool bindings; it invokes neither model nor tools until explicit `SubagentSession.resume`. Current authorization still applies. Idle restoration requires complete local tool history; retained provider progress is conversation data, not unfinished local execution.

The session turn permit covers command execution, joined run cleanup, atomic snapshot and save. A rejected send cannot replace a suspended checkpoint. A resume that claimed the checkpoint and then failed saves the runtime's resulting state. Cancellation still attempts the save after joined recovery cleanup. Persistence I/O must be host-bounded because this final save completes under the ownership mask. Original run failures/interruption and save failures are preserved together. A failed, conflicting or uncertain save poisons the runtime: later commands fail before model/tool execution until explicit retirement/reopen. No write or command automatically retries or replays.

[SubagentTools.forNamedSessions](SubagentTools.scala) explicitly installs `agent_spawn` and `agent_send` with exact `agent_id`, `label` and `prompt` string fields. Both select the same registration and return a typed `SubagentNamedToolResult`; they never implicitly resume a checkpoint. Host code uses the returned session's existing execution registry and checked `resume` API for task observation, cancellation and confirmation delivery. Existing unbound session/tool APIs retain their behavior. The backend's lifetime, authenticated namespace, exclusive claims, migration backups and confirmation idempotency remain host responsibilities.

The [public lifecycle tests](../../../../../../../test/scala/com/weisgnosis/agents/harness/subagent/SubagentNamedSessionsSpec.scala) and [persistence tests](../../../../../../../test/scala/com/weisgnosis/agents/harness/subagent/SubagentNamedSessionStoreSpec.scala) cover reuse/reopen, current policy, strict storage, failed admission and save uncertainty. These scenarios exercise the public named-session lifecycle; they do not certify distributed fencing or a durable event journal.

## Shared task files

[SharedSubagentTaskFiles](SharedSubagentTaskFiles.scala) binds a borrowed `TaskFileBackend`, an explicit owner `StorageAddress` and a checked agent name. Its `read` and `write` operations accept only `agents/<bound-agent>/tasks/<checked-session>.json`. The backend receives the exact bytes, including non-JSON and non-UTF-8 data, at namespace `owner.namespace ++ Chunk(owner.key, agent, session)` and key `tasks`. Distinct owners and sessions therefore have separate addresses. Rebinding the same owner to the same backend reads the existing file.

The host authenticates the owner and keeps the borrowed backend alive; this route neither acquires nor closes it. Invalid or foreign paths fail before backend access. Missing files, backend failures and cancellation never fall back to local files or another owner. A positive byte limit bounds accepted reads and writes; the backend must separately bound allocation and transfer. Reads over the limit fail without truncation, and oversized writes never reach the backend. Address capacity is validated for each full namespace.

This is the task-file routing behavior of pinned `WorkspaceTaskRepositoryTest.remoteFilesystemSpec_includesTasksRoute` (857), exposed as an explicit capability rather than a general composite filesystem. It grants no task registration, execution, JSON/CAS semantics, network transport or delivery-order guarantee. ## Persisted execution origin

SubagentExecutionOrigin distinguishes Local from AgentProtocol with a checked exact SubagentProtocolBaseUri. Endpoint observations permit bounded absolute HTTP(S), including an @ in a path, and reject authority credentials, query, fragment, malformed Unicode and whitespace/control characters. This is pure structural validation, not DNS access, an endpoint client or an execution capability. The stricter URI policy is an intentional Scala admission boundary.

The built-in store writes strict schema 8 with required origin and remoteApproval. Dedicated original-representation readers accept schemas 1–7 without rewriting storage or inventing dates. Schemas 1–6 normalize absent origin to Local; schema 7 preserves its required origin. Legacy records gain NotAwaiting only after strict original-wire validation. Unknown/duplicate fields, malformed Unicode and byte/count limits remain checked. Older readers reject schema 8; coordinate reader/writer upgrades and backups. SubagentTaskRecord now has seven fields, with trailing remoteApproval defaulting to NotAwaiting. Update positional extractors/Product handling and rebuild constructor/copy/accessor users. Admission and terminal identities retain their existing arities and exact origin; no binary compatibility is promised.

Host-only admitAgentProtocol and confirmAgentProtocolStart persist remote Pending/Running observations without creating local execution. Ordinary local start and heartbeat reject remote records; exact admission, cancellation and terminal-publication identity includes origin. Acknowledgement and terminal projection retain it. Local stale-owner recovery excludes persisted AgentProtocol before acquiring host authority, and the local permit/CAS boundary also rejects it. A remote Created response from a custom store cannot release a local child; rejected admission joins rollback and preserves cleanup failures.

## Explicit remote task observation

[SubagentRemoteTask.attach](SubagentRemoteTask.scala) borrows a host-supplied SubagentRemoteTransport for one exact already admitted AgentProtocol task. The selected transport endpoint must match persisted origin; the complete task ID, worker, original creation time and origin must match. Attachment performs no transport request. The transport has no submit operation, and stored URI data never creates a network capability or local executor. Hosts own peer authentication, bounded transport resources and execution fencing.

`observe` joins one transport request before conditionally applying its result to the exact sampled record. A changed nonterminal record rejects stale data; same-identity terminal truth wins and retains its acknowledgement. Pending cannot regress Running. Explicit `await(WaitTimeout)` owns bounded polling without a daemon and returns promptly for terminal, Awaiting or ConfirmationClaimed data. Positive budgets include admission, storage, request and polling; timeout zero performs one host-bounded observation without a timer. Timeout/caller cancellation joins owned request cleanup and never sends remote cancellation. Cleanup can extend the budget; independent failures/defects remain observable.

Remote approval uses NotAwaiting, Awaiting, ConfirmationClaimed and Resolved. Awaiting carries at most 128 unique checked calls and a positive task-local monotonically increasing generation guaranteed by the trusted transport. `confirm(expectedGeneration, decisions)` requires the exact host-observed generation and complete ordered call IDs. An exact-record CAS persists the generation, calls and decisions as ConfirmationClaimed before contacting the captured transport. A competing, stale or malformed receipt fails before sending. Uncertain storage/transport errors and interruption do not replay the decision. Reopening and ordinary Running/same-batch observations preserve Claimed; only explicit trusted resolution, a strictly newer approval generation or terminal truth retires it. Old generations and changed/reused same-generation batches fail closed.

Generation binds consent to one batch; it is not user authentication or exactly-once remote execution. The pinned Java HTTP protocol does not supply a stable generation. A future binding must establish that guarantee independently before enabling confirmation; it must not manufacture it from repeated call IDs. No concrete HTTP AgentProtocol client, remote event stream or distributed claim implementation is included.

`requestCancellation` persists exact-identity cancellation intent before contacting the remote transport. Only subsequent remote terminal truth establishes completion. A repeated explicit call retries delivery, so the host transport must tolerate repetition; ordinary observation/polling never resends it. Confirmation claims and remote effects are not one atomic transaction. The host owns reconciliation after uncertain delivery.

The [remote suite](../../../../../../../test/scala/com/weisgnosis/agents/harness/subagent/SubagentRemoteTaskSpec.scala) covers stale consent, forged receipts, competing handles, uncertainty, strict migration, identity and joined cleanup. The existing [PostgreSQL task scenario](../../../../../../../../../storage-postgresql/src/test/scala/com/weisgnosis/agents/storage/postgresql/PostgresSubagentTerminalStoreSpec.scala) checks approval/claim persistence through independent adapters. This adapts pinned WorkspaceTaskRepository's attachment without resubmission through an explicit host capability rather than an implicit poller.

## Local task workspace

LocalSubagentTaskWorkspace explicitly binds agents/<agent>/tasks/<session>.json to StorageAddress(Chunk(agent, session), "tasks"). Checked portable names are separate from storage addresses. openSession owns a local writer; listRecent discovers session-separated observations without acquiring writer ownership, creating directories, acknowledging output or restoring execution. The recent window uses actual file modification times, including equality at the cutoff, rather than task timestamps. One suspended Clock sample supplies the cutoff. An absent valid agent/tasks directory returns empty; an existing invalid layout, selected corrupt file or disappeared selected file fails. Neither records nor file modification times establish executor liveness, ownership or a global atomic snapshot.

## Host-driven task recovery

recoverStaleTasks(policy, claimGate, authority) operates only on this durable registry's bound store. Volatile/custom registries and custom stores default to typed unsupported failures. The host explicitly invokes recovery; the library installs no sweeper or scheduling daemon.

Policy.make defaults to the pinned upstream 10.minutes staleAfter and 5.minutes minGap, and checks nonnegative finite durations strictly below Duration.Infinity. Gate.local allocates its Ref in ZIO, claims atomically using monotonic time and refuses backward time. One gate instance belongs to one host-selected scheduling domain. The gate is claimed once before task-store scanning and publication-clock sampling; denied attempts perform neither. Admitted attempts consume their interval even if later work fails or is interrupted. The gate is a throttle, never an execution lease or distributed claim.

An admitted sweep samples one observedAt and selects metadata-bearing Pending/Running records whose lastUpdatedAt is at or before observedAt minus staleAfter. Fresh, terminal and legacy records without metadata are excluded. An out-of-range cutoff fails explicitly. Timestamps select candidates; they never prove that an executor is abandoned.

Known retained local entries are skipped before requesting host authority, including paused execution and completed workers whose publication/notification ownership remains retained. This initial read is conservative. Authority.acquire receives this exact registry capability and candidate outside the admission gate. Its child Scope must hold the host's actual ownership/fencing resources for this registry's bound storage partition, not a different partition with equal task data. Remote, OwnerPresent and Unknown decisions perform no recovery write. A Local permit must match the exact candidate. Permit.local is only a checked host assertion; never cache/reuse it after the ownership scope closes or mistake it for a fence.

Before mutation, recovery acquires the same admission gate as submission, rechecks Open state and every retained local ID, then performs conditional publication under that gate. This second check protects tasks admitted while host authority was acquired. Authority acquisition and cleanup run outside the gate; no worker or publisher is joined inside it. Hosts must avoid callbacks/cleanup that create ownership cycles with this registry or its owner scopes.

SubagentTerminalStore.reconcileAbandoned compares the complete expected record on every CAS attempt. Missing returns Missing; any identity, state, timestamp, check, intent or terminal change returns Changed without replacement. An unchanged nonterminal becomes Failed with typed message "executor lost", no invented direct cause/defects, Pending acknowledgement and lastUpdatedAt equal to observedAt. Creation/check times, worker identity and cancellation intent remain intact; the new terminal observation moves to the publication tail. Storage follows the [current schema-8 approval/origin migration](#persisted-execution-origin), preserving exact origin. Only confirmed conflicts retry, with the same permit and observedAt; uncertain failures and cancellation never retry automatically.

Recovery processes candidates sequentially and stops on failure or interruption. Previously committed observations remain committed; failure/cancellation is not rollback or proof of non-publication. Cancellation joins host authority cleanup and preserves its defects together with the caller cause, without cancelling task workers. Reconciled output remains pending normal consumption; recovery performs no acknowledgement, notification replay, model request or executable checkpoint restoration. A later admission colliding with recovered terminal truth cannot start a child.

The [persisted-origin contract](#persisted-execution-origin) implements method687 exclusion before local authority acquisition. The [shared task-file route](#shared-task-files) and [named idle/suspended restoration](#persistent-named-sessions) are implemented. Recovery of executing children remains separate; endpoint transport and distributed ownership/fencing are host capabilities.

## Explicit owner heartbeat

refreshCurrentOwner is an explicit host operation over one captured Open registry membership. It polls actual retained tasks and refreshes only unfinished local handles with confirmed admission identities. Completed handles are skipped without backend work; an empty durable registry performs no storage or clock work. Closed durable registries reject the operation before backend access. Volatile/custom registries and custom stores default to typed unsupported failures; there is no implicit maintenance fiber.

SubagentTerminalStore.refreshHeartbeat validates the exact task ID, worker and original creation time on every aggregate read. Only Running with NotRequested intent updates lastUpdatedAt. Pending, Terminal and requested-cancellation records return NotRunning, AlreadyTerminal or CancellationRequested unchanged, with no clock sample or write; terminal disposition takes precedence. Refreshed returns the exact confirmed record. Missing or mismatched admission fails closed. The store preserves creation/check times, outcome, acknowledgement, cancellation intent, execution origin and aggregate order under the [current schema-8 migration](#persisted-execution-origin); exact heartbeat identity is local-only and includes origin.

One eligible logical refresh samples a clock candidate, reused only after confirmed CAS conflicts. Every retry rechecks identity/state/intent; a terminal or cancellation winner prevents another write. Uncertain writes are not retried. Wall-clock values may move backward and are recorded as observed. These timestamps do not constitute an execution lease, fencing or proof of owner liveness.

Registry attempts run sequentially in captured order. Ordinary typed errors are retained while later independent entries are attempted, then combined as exact Causes. Defects or interruption stop the traversal immediately with earlier failures and the actual stopping/cleanup cause preserved. Cancellation joins the current refresh operation without signalling task workers or publishers; prior committed refreshes are not rolled back. A task may complete after its eligibility poll, and closure may begin after membership capture. Store CAS guards persisted state; hosts serialize refresh with owner shutdown when they need a quiescent boundary. No stored-only record creates a handle or becomes refresh authority.

## Ownership, cancellation and promotion

## Bounded task registry

`SubagentTaskRegistry.open(parent, factory, maxTracked = 256)` acquires a registry in a host Scope and requires positive capacity. Each `submit` creates a fresh configured child through the retained factory and parent spawner. Accepted submissions return a registry-local UUID task ID; other outcomes are Capacity, Closed or IdentityCollision. Depth rejection remains a typed spawn error. Rejected admission acquires no child factory resources and retains no record. IDs identify execution records within one registry; they are not durable sessions or standalone authority.

Capacity counts every retained record, including completed results. `forgetCompleted` removes only terminal work, returning Removed, Running or Missing. This frees record capacity without restarting or replacing a child. The bound is a record count, not a bound on the bytes retained by full AgentResult histories and causes. Hosts must retire completed records according to their retention needs.

`inspect` and `list` observe Running or Completed with a complete Exit, preserving typed failures, defects, interruption and cleanup causes. A list captures membership once and polls each entry independently; it is not an atomic completion snapshot. Lookup-based await, promotion and cancellation return None for missing IDs and otherwise delegate to the existing task handle. They do not hold the admission permit while waiting or joining cleanup. Completed records remain inspectable after registry closure until explicitly forgotten or the registry becomes unreachable.

Each submission owns a private caller cancellation lease. Admission records the task before attaching that lease's finalizer to the caller Scope, outside the admission permit. An already closed caller can therefore join its child cleanup without hiding the retained record or blocking unrelated capacity checks. Closing a normal caller cancels and joins attached work; promoted work survives caller closure. Closing the registry first closes admission, then cancels registered tasks in parallel and joins cleanup, including promoted tasks, even if the underlying supervisor outlives the registry. Public `open(parent, factory)` creates fresh children; the session uses a package-private launcher to retain its runtime. Neither registry provides remote ownership or durable restart recovery.

## Directory-bound model routing

`SubagentTools.forDirectory(directory)` supplies `agent_send`, `agent_task` and `agent_cancel` within one host-selected directory. Send requires exactly two string fields, `session_id` and `prompt`; task inspection/cancellation require exactly `session_id` and `task_id`. IDs require canonical UUID shape. Missing, duplicate, extra or wrong-type fields are rejected before lookup or work. The host supplies known membership IDs to the model; the toolkit has no discovery, construction, registration, removal or directory-closure tool.

Each invocation looks up a ready membership and then uses that session's execution registry. [SubagentSessionToolResult](SubagentTools.scala) wraps accepted routing as `Session(sessionId, result: SubagentToolResult)` and missing membership as `Missing(sessionId)`. Rejections and child failures retain the selected session in the wrapped Error observation; a task ID from another session remains Missing within the selected session result. Caller interruption remains interruption. Fixed-registry and fixed-session result shapes are unchanged.

Lookup is a membership snapshot, not atomic revocation. Removal or closure hides subsequent lookup and joins owned cleanup, but an invocation that already obtained the session can race with closure. Original resource owners still bound lifetime; membership may refer to an externally closed session, whose send returns a wrapped Closed rejection. Routed sends use the selected host execution policy and joined task cancellation; inspection/cancellation do not make another model request. Installing routing grants no new child tools, policy inheritance or approval authority. The host retains the directory and original resource/supervisor scopes for intended background work.

## Subagent milestones

Hosts opt in with checked [SubagentLifecycleMetadata.from](SubagentLifecycleMetadata.scala): exact parent session ID, child session ID, agent ID and optional label, each nonblank valid Unicode within 1,024 UTF-8 bytes. Pass the result as `lifecycle = Some(metadata)` to `SubagentTaskRegistry.open`/`openDurable` or `SubagentSession.open`/`openRestored`. Metadata is descriptive correlation, never routing, execution or approval authority. Task UUIDs remain execution-source prefixes; they are not substituted for session identities. Existing calls default to no milestone emission, and detached tool execution supplies no event destination.

With an active `ToolEventPort`, each accepted execution attempts `SubagentSpawnEvent`, including every send to a reused session. `SubagentStartEvent` marks entry into execution; a reusable session emits it only after acquiring its turn permit, without moving the existing durable running transition. An accepted execution cancelled before that point can emit Spawn and End without Start. The registry registers its scoped End watcher before releasing execution. `SubagentEndEvent` waits for the Spawn publication attempt and the actual worker's joined cleanup, then derives completed, suspended, stopped, interrupted or failed status from the retained typed outcome. End is not a terminal-publication or acknowledgement receipt.

For persistent named sessions, select `lifecycleEvents = SubagentLifecycleEvents.Enabled` in `SubagentNamedSessions.open`. Before exposing the session, the owner binds the actual directory registration ID with the checked parent/agent/label key. Reused spawn/send calls share that child session identity while retaining distinct task-source IDs. Reopening creates a fresh registration; persisted history does not confer identity or event authority.

Completed synchronous waits and cancellation that joins a captured local worker also join the watcher. An AlreadyTerminal cancellation response retains its existing immediate stored-truth semantics. Registry closure joins owned watchers outside the admission gate; `forgetCompleted` returns `MilestonesPending` while a watcher is unfinished or failed. No daemon, delivery journal or replay is installed. A closed parent publication port drops later attempts, including after promotion; an abandoned stream consumer is not promised its tail. The existing nested forwarding path preserves milestone source prefixes while keeping host-selected session fields intact.

## Scoped child event forwarding

Model-facing spawn/send tools propagate the current `ToolInvocation.Active.events` through fixed registries, catalogs, bound sessions and directories. Each registry allocates its execution UUID before launch and uses it as the event source prefix; nested child sources append with `/`. Names and model call IDs do not supply this identity. Child request/reply correlation remains unchanged, parent events retain their own source, and child lifecycle events come from the actual runtime rather than synthetic duplicate bookends.

Factory and session workers use the core [direct forwarding primitive](../../../../../../../../../core/src/main/scala/com/weisgnosis/agents/core/agent/README.md#direct-event-forwarding) within existing supervisor ownership. Registry snapshots retain complete results and failure causes. Each session send captures a fresh port; neither the shared session nor factory stores an invocation destination. Inspection/cancellation does not attach a new destination or replay events.

Returning Promoted after the existing 30-second wait ends the tool invocation and revokes its publication lease. The supervised child continues once and retains its outcome; later events are dropped. Live event forwarding has no replay, acknowledgement or backpressure; the separate completion inbox acknowledges retained terminal outcomes only. Cancelling a public stream consumer still abandons subsequent output, even though owned cancellation joins cleanup. A separately retained active observer does receive the child lifecycle End after parent execution is interrupted and child cleanup joins. The actual nested fixture verifies exactly one Start/End with the runtime task source and matching nonempty reply ID, child End before parent End, and the retained child interrupted Exit. The observer outlives the cancelled parent execution; this does not extend a cancelled public consumer's publication lifetime.

Migration: existing `submit(input)`, `send(input)` and factory spawn calls retain detached behavior. The additive registry `submit(input, events)` and session `send(input, events)` accept an optional host-held port. Existing custom registry implementations remain source-compatible through a detached default; they must override the new overload to support forwarding. Port possession is an explicit runtime capability, not serializable model input. Hosts remain responsible for retaining supervisor scopes for promoted work.

## Named session catalog

[SubagentSessionCatalog.open](SubagentSessionCatalog.scala)(parent, entries, maxSessions = 64, maxTrackedPerSession = 256) returns scoped `TaskResourceAdmission[SubagentSessionCatalog]`. The host supplies a finite ordered set of `SubagentEntry` factories. Exact names/descriptions must be nonblank, names unique, capacities positive and entry count within the session bound before any acquisition. Installation eagerly initializes each eligible session but makes no model request. Factory callbacks and raw factories remain trusted host capabilities; factories composed through SubagentConstruction retain their installed static and live policy restrictions.

One owned initializer acquires the entire catalog; any partial failure, defect, caller cancellation or owner closure joins rollback before returning. Its private context spawner preserves the parent lineage without allocating an identity or consuming depth. Each retained session still allocates one descendant UUID and passes the existing depth admission. The context supervisor is the sole automatic session-resource owner. Its private directory index manages membership without another automatic resource-close obligation, so aggregate closure joins nested work and resource cleanup without replaying the same defect through duplicate ownership edges.

`entries` remains the immutable descriptive input. `lookup(name)` resolves current membership to a session ID and its initialized session; repeated lookups reuse that runtime/history, while different names and catalogs have isolated sessions. `remove(name)` hides the entry, joins its existing resource closure and never recreates it. Lookup is a snapshot, not an atomic liveness guarantee: aggregate closure may leave membership visible while cleanup is underway, then closes the index. Existing task retention bounds apply per session; completed records still require host retention policy.

Close the returned resource to close the aggregate, or end its acquiring caller/supervisor scope. Session workers and finalizers must not remove themselves or await their own catalog/resource closure. Model-facing named routing is an opt-in adapter below. This fixed catalog adds no dynamic arbitrary labels or automatic policy installation through raw factories; [persistent named sessions](#persistent-named-sessions) separately supplies stable reuse keys and idle/suspended restoration. Public SubagentSession.open and SubagentSessionDirectory.open retain their existing caller-lease and closure behavior.

## Named session tools

`SubagentTools.forSessionCatalog(catalog)` adds opt-in `agent_send`, `agent_task` and `agent_cancel` bound to one host-installed catalog. Send requires exactly string `agent_id` and `prompt`; task/cancel require exactly string `agent_id` and canonical UUID `task_id`. Duplicate or extra fields are rejected. Exact names select current membership only: unknown or removed names return Missing, foreign task IDs cannot reach another registry, and no call creates or replaces a session. Tool descriptions expose the immutable entry names/descriptions, including entries subsequently removed.

The existing `SubagentCatalogToolResult` carries selected agent identity and bounded task observations; there is no new session-ID DTO. Typed execution errors retain selected identity, while malformed-input and defect diagnostics keep existing Toolkit normalization. Each accepted send reuses the selected runtime/history but gets a fresh execution ID and current invocation event port. The selected host execution policy and joined cancellation apply, with same-execution promotion by default; inspection/cancellation do not create a model request. Full results and cleanup causes remain in the selected registry.

Migration: this is an additive toolkit factory. `forCatalog` still spawns fresh children, and fixed-session/directory call sites are unchanged. The adapter grants no factory selection, dynamic labels, recreation, durable keys, restoration or new approval authority. Lookup remains a snapshot subject to owner closure.
