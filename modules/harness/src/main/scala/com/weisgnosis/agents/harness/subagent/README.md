# Scoped child execution and sessions

## Persistent named sessions

[SubagentNamedSessions.open](SubagentNamedSessions.scala) owns a bounded set of reusable child sessions selected by exact `(parentSessionId, agentId, label)`. The host supplies fixed current `SubagentEntry` factories, a borrowed [SubagentNamedSessionStore](SubagentNamedSessionStore.scala) and an `Authority` that acquires an exclusive claim for the exact registration/address. The claim must remain valid until runtime cleanup finishes. CAS detects conflicting persistence; it is not an execution fence or authentication mechanism.

`getOrOpen` shares one Promise per key and performs acquisition outside the short membership transition. Other keys can initialize independently. A waiting caller can cancel its wait without cancelling the initializer. Cancelled or failed initialization joins owned runtime/claim cleanup, resolves the shared Promise with its cause and retains a bounded failed slot. `retire` explicitly removes a failed slot, or joins an existing runtime before allowing a later generation. Callbacks must not close their own resource owner.

The strict version-1 envelope contains the checked registration and one `AgentSnapshot`: `Idle(history)` or `Suspended(AgentResult)`. It contains no live task, factory, policy or claim. Reopening acquires the current host claim first, loads bounded data and creates a fresh runtime through the supplied factory. Suspended restoration validates the checkpoint/current tool bindings; it invokes neither model nor tools until explicit `SubagentSession.resume`. Current authorization still applies. Idle restoration requires complete local tool history; retained provider progress is conversation data, not unfinished local execution.

The session turn permit covers command execution, joined run cleanup, atomic snapshot and save. A rejected send cannot replace a suspended checkpoint. A resume that claimed the checkpoint and then failed saves the runtime's resulting state. Cancellation still attempts the save after joined recovery cleanup. Persistence I/O must be host-bounded because this final save completes under the ownership mask. Original run failures/interruption and save failures are preserved together. A failed, conflicting or uncertain save poisons the runtime: later commands fail before model/tool execution until explicit retirement/reopen. No write or command automatically retries or replays.

[SubagentTools.forNamedSessions](SubagentTools.scala) explicitly installs `agent_spawn` and `agent_send` with exact `agent_id`, `label` and `prompt` string fields. Both select the same registration and return a typed `SubagentNamedToolResult`; they never implicitly resume a checkpoint. Host code uses the returned session's existing execution registry and checked `resume` API for task observation, cancellation and confirmation delivery. Existing unbound session/tool APIs retain their behavior. The backend's lifetime, authenticated namespace, exclusive claims, migration backups and confirmation idempotency remain host responsibilities.

The [public lifecycle tests](../../../../../../../test/scala/com/weisgnosis/agents/harness/subagent/SubagentNamedSessionsSpec.scala) and [persistence tests](../../../../../../../test/scala/com/weisgnosis/agents/harness/subagent/SubagentNamedSessionStoreSpec.scala) cover reuse/reopen, current policy, strict storage, failed admission and save uncertainty. These scenarios exercise the public named-session lifecycle; they do not certify distributed fencing or a durable event journal.

## Shared task files

[SharedSubagentTaskFiles](SharedSubagentTaskFiles.scala) binds a borrowed `TaskFileBackend`, an explicit owner `StorageAddress` and a checked agent name. Its `read` and `write` operations accept only `agents/<bound-agent>/tasks/<checked-session>.json`. The backend receives the exact bytes, including non-JSON and non-UTF-8 data, at namespace `owner.namespace ++ Chunk(owner.key, agent, session)` and key `tasks`. Distinct owners and sessions therefore have separate addresses. Rebinding the same owner to the same backend reads the existing file.

The host authenticates the owner and keeps the borrowed backend alive; this route neither acquires nor closes it. Invalid or foreign paths fail before backend access. Missing files, backend failures and cancellation never fall back to local files or another owner. A positive byte limit bounds accepted reads and writes; the backend must separately bound allocation and transfer. Reads over the limit fail without truncation, and oversized writes never reach the backend. Address capacity is validated for each full namespace.

This is the task-file routing behavior of pinned `WorkspaceTaskRepositoryTest.remoteFilesystemSpec_includesTasksRoute` (857), exposed as an explicit capability rather than a general composite filesystem. It grants no task registration, execution, JSON/CAS semantics, network transport or delivery-order guarantee. [SharedSubagentTaskFilesSpec](../../../../../../../test/scala/com/weisgnosis/agents/harness/subagent/SharedSubagentTaskFilesSpec.scala) exercises the public byte route, owner/session isolation, rejected paths, failures and joined cancellation.

## Host-driven task recovery

recoverStaleTasks(policy, claimGate, authority) operates only on this durable registry's bound store. Volatile/custom registries and custom stores default to typed unsupported failures. The host explicitly invokes recovery; the library installs no sweeper or scheduling daemon. Both independent reviewers approve the six exact Scala identities below; full/artifact/archive/consumer verification passes; review_fp and review_invariants approve the final combined scope against b4e3b37: six unchanged Scala identities and fourteen Markdown files, with no unresolved findings.

Policy.make defaults to the pinned upstream 10.minutes staleAfter and 5.minutes minGap, and checks nonnegative finite durations strictly below Duration.Infinity. Gate.local allocates its Ref in ZIO, claims atomically using monotonic time and refuses backward time. One gate instance belongs to one host-selected scheduling domain. The gate is claimed once before task-store scanning and publication-clock sampling; denied attempts perform neither. Admitted attempts consume their interval even if later work fails or is interrupted. The gate is a throttle, never an execution lease or distributed claim.

An admitted sweep samples one observedAt and selects metadata-bearing Pending/Running records whose lastUpdatedAt is at or before observedAt minus staleAfter. Fresh, terminal and legacy records without metadata are excluded. An out-of-range cutoff fails explicitly. Timestamps select candidates; they never prove that an executor is abandoned.

Known retained local entries are skipped before requesting host authority, including paused execution and completed workers whose publication/notification ownership remains retained. This initial read is conservative. Authority.acquire receives this exact registry capability and candidate outside the admission gate. Its child Scope must hold the host's actual ownership/fencing resources for this registry's bound storage partition, not a different partition with equal task data. Remote, OwnerPresent and Unknown decisions perform no recovery write. A Local permit must match the exact candidate. Permit.local is only a checked host assertion; never cache/reuse it after the ownership scope closes or mistake it for a fence.

Before mutation, recovery acquires the same admission gate as submission, rechecks Open state and every retained local ID, then performs conditional publication under that gate. This second check protects tasks admitted while host authority was acquired. Authority acquisition and cleanup run outside the gate; no worker or publisher is joined inside it. Hosts must avoid callbacks/cleanup that create ownership cycles with this registry or its owner scopes.

SubagentTerminalStore.reconcileAbandoned compares the complete expected record on every CAS attempt. Missing returns Missing; any identity, state, timestamp, check, intent or terminal change returns Changed without replacement. An unchanged nonterminal becomes Failed with typed message "executor lost", no invented direct cause/defects, Pending acknowledgement and lastUpdatedAt equal to observedAt. Creation/check times, worker identity and cancellation intent remain intact; the new terminal observation moves to the publication tail. Storage follows the [current schema-7 origin migration](#persisted-execution-origin), preserving exact origin. Only confirmed conflicts retry, with the same permit and observedAt; uncertain failures and cancellation never retry automatically.

Recovery processes candidates sequentially and stops on failure or interruption. Previously committed observations remain committed; failure/cancellation is not rollback or proof of non-publication. Cancellation joins host authority cleanup and preserves its defects together with the caller cause, without cancelling task workers. Reconciled output remains pending normal consumption; recovery performs no acknowledgement, notification replay, model request or executable restoration. A later admission colliding with recovered terminal truth cannot start a child.

## Explicit owner heartbeat

refreshCurrentOwner is an explicit host operation over one captured Open registry membership. It polls actual retained tasks and refreshes only unfinished local handles with confirmed admission identities. Completed handles are skipped without backend work; an empty durable registry performs no storage or clock work. Closed durable registries reject the operation before backend access. Volatile/custom registries and custom stores default to typed unsupported failures; there is no implicit maintenance fiber.

SubagentTerminalStore.refreshHeartbeat validates the exact task ID, worker and original creation time on every aggregate read. Only Running with NotRequested intent updates lastUpdatedAt. Pending, Terminal and requested-cancellation records return NotRunning, AlreadyTerminal or CancellationRequested unchanged, with no clock sample or write; terminal disposition takes precedence. Refreshed returns the exact confirmed record. Missing or mismatched admission fails closed. The store preserves creation/check times, outcome, acknowledgement, cancellation intent, execution origin and aggregate order under the [current schema-7 migration](#persisted-execution-origin); exact heartbeat identity is local-only and includes origin.

One eligible logical refresh samples a clock candidate, reused only after confirmed CAS conflicts. Every retry rechecks identity/state/intent; a terminal or cancellation winner prevents another write. Uncertain writes are not retried. Wall-clock values may move backward and are recorded as observed. These timestamps do not constitute an execution lease, fencing or proof of owner liveness.

Registry attempts run sequentially in captured order. Ordinary typed errors are retained while later independent entries are attempted, then combined as exact Causes. Defects or interruption stop the traversal immediately with earlier failures and the actual stopping/cleanup cause preserved. Cancellation joins the current refresh operation without signalling task workers or publishers; prior committed refreshes are not rolled back. A task may complete after its eligibility poll, and closure may begin after membership capture. Store CAS guards persisted state; hosts serialize refresh with owner shutdown when they need a quiescent boundary. No stored-only record creates a handle or becomes refresh authority.

## Completion notifications

SubagentCompletionNotification is an explicit host policy: Suppress or Notify(SubagentCompletionNotifier). openDurable captures the configured default; submitWithCompletionNotification supplies a host-only per-submission override. Model metadata cannot choose suppression. Borrowed SubagentTerminalBinding passes the same policy through public catalog/session factories without transferring backend ownership. Ordinary volatile registries retain their existing behavior and reject the new capability with a typed unsupported error.

Each accepted durable task owns its notifier before execution is released. The notifier waits for actual joined execution/cleanup and the captured confirmed publication, then invokes the suspended callback in its own Scope with the exact terminal record and publication receipt. Failed or uncertain publication never invokes the callback. No acknowledgement, model request, durable callback replay or background scheduler is introduced. Pinned WorkspaceTaskRepositoryTest methods882/923 are adapted through truthful joined terminal persistence and suppressed/notified submissions in one registry; remote wakeups and restart recovery remain separate obligations.

completionNotification(id) and flushCompletionNotifications expose runtime receipts: Suppressed, Observed or NotPublished(exact publication Cause). Callback failures, defects and interruption remain exact failures of their owned notification receipt; they do not rewrite terminal truth or duplicate publication failure. Flush captures membership and joins every receipt before combining failures. Cancelling a receipt observer does not cancel the notifier. Legacy close joins task, publisher and notifier cleanup; hosts must inspect the explicit receipt/flush port for typed callback failures, which remain available after closure.

Pending or failed callbacks prevent forgetting with SubagentTaskRemoval.Unnotified and retain their place within maxTracked. Successful Suppressed/Observed receipts permit existing retirement; failed publication retains the existing Unpublished result. Notification is a process-lifetime observation, not proof of external delivery or exactly-once execution. Reopening stored records never replays callbacks.

Callbacks may inspect persisted records without holding admission locks. The callback context, including inherited child fibers, rejects notification receipt/flush self-waits. Callbacks must not close their captured registry, supervisor or borrowed owner scope, await their own execution, or create cross-owner callback cycles. Hosts bound callback/backend runtime and join any children whose successful work matters; the callback Scope joins owned cleanup before recording completion.

## Ownership, cancellation and promotion

`TaskSupervisor.open[A]` creates an execution owner in the host Scope. `attach` accepts a suspended scoped task and a separate parent cancellation lease. Admission is serialized against host closure; closed admission evaluates no task callback. Launch registration is masked, but task execution remains interruptible. Task effects and completion waits never hold the admission permit.

The supervisor owns each fiber from launch. Closing the attaching parent Scope cancels attached work and joins all task cleanup, including cleanup already started by explicit cancellation. `await` observes the complete Exit without cancelling. `poll` observes completed work without waiting and reports completion only after owned cleanup finishes. `cancel` also stops promoted work and waits for cleanup. Parent/host finalizers join tasks; task failures remain in the handle Exit. Live handles, admissions and lineage capabilities have no JSON codecs.

`awaitOrPromote` races completion against a fresh 30-second budget on each call, without restarting work. Only the winning timer's masked transition promotes the attached lease. Released work cannot be promoted. Promoted work survives parent closure; explicit cancellation and host closure still stop it. At simultaneous completion/deadline, the race winner decides. Cancelling a waiting observer does not by itself cancel the task or reverse committed promotion.

Host shutdown closes worker scopes in parallel, preventing one blocked finalizer from postponing interruption of other workers. Each worker closes its own sequential scope on completion, avoiding the ZIO 2.1.26 `forkIn` self-join deadlock. Task resources keep ordinary scoped cleanup and complete failure causes. Explicitly masked work or blocked finalizers can delay cancellation indefinitely. Tasks/finalizers must not wait for an owner or parent whose closure is joining them, or for their own handle. The host must retain its Scope for all desired background work; no daemon lifetime, remote adoption or restart durability exists.

## Shared resource ownership

`TaskSupervisor.own(initialize)` acquires a [TaskResource](TaskResource.scala) in both the supervisor and acquiring caller Scope. Closed admission evaluates no initializer. The initializer receives a nested supervisor and runs interruptibly; its scoped acquisitions outlive initialization and individual nested tasks. Initialization failure, defect or cancellation joins partial cleanup before returning, preserving the failure Exit supplied to resource finalizers.

Explicit `resource.close`, acquiring-caller finalization and supervisor shutdown share one closure authority. It closes nested admission, joins initialization and all nested workers (including queued and promoted work), then releases shared resources exactly once. Competing library close paths wait for the same complete cleanup outcome, including defects. The first close supplies the resource finalizer Exit: explicit close and normal supervisor shutdown use success; an initialization failure or caller finalizer can supply failure. This does not alter concurrent calls to a raw ZIO `Scope.close`. Completed resource registrations detach from the supervisor.

`TaskSupervisor.ownRetained(initialize)` uses the same admission, initialization and cleanup kernel without adding a caller-scope lease. After successful acquisition, only the supervisor lifetime and explicit resource closure bound retention. Failure or cancellation during acquisition joins the reserved owner before returning. For `own`, the host must still retain the acquiring Scope for the intended resource lifetime. Owned workers and finalizers must not close or await their own resource owner. Resource values and handles are process-local capabilities, with no codecs, session lookup, restart recovery or child-runtime reuse implied.

Migration: `TaskSupervisor` now requires abstract `ownRetained[B](TaskSupervisor[A] => ZIO[Scope, AgentError, B]): IO[AgentError, TaskResourceAdmission[B]]` in addition to `own`. This is source-incompatible for existing custom implementations. Custom implementations, decorators and test doubles must implement or delegate the retained ownership contract; there is no default fallback. Wrapping `own` in a short-lived `ZIO.scoped`, or using `attach`, would release resources too early. Public `own` retains its caller-scope lease semantics.
