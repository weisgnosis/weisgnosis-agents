# MCP tool binding verification

[McpModelInputTransformSpec](McpModelInputTransformSpec.scala) supplies one grouped custom/media/settings boundary table. McpToolSpec also executes the actual MCP tool through ReAct and serializes the second model request, preserving exact canonical resource data. The [request-projection contract](../../../../../../../main/scala/com/weisgnosis/agents/mcp/tool/README.md#request-only-custom-content-projection) describes opt-in request projection and media limits.

The [embedded resource projection parity task](../../../../../../../main/scala/com/weisgnosis/agents/mcp/tool/README.md#embedded-resource-projection-parity) covers the named finite behavior. The grouped regression reproduces the missing visible projection against unchanged production and checks pinned text/image/binary-description behavior together with retained Custom payloads and inner/outer metadata.

Toolkit construction and selection follow the [checked registry identity and migration contract](../../../../../../../../../core/src/main/scala/com/weisgnosis/agents/core/tool/README.md#checked-registry-identity). The linked contract describes migration; existing lifecycle and permission contracts remain in force.

[McpToolSpec](McpToolSpec.scala) checks contracts using an initialized client and controlled borrowed transport:

- A table reproduces embedded-resource text/image/binary-description parity and preserves both raw bodies, inner/outer metadata, result state and no additional network invocation.
- Fixed remote routing through an actual ReAct continuation preserves host ToolDef authority, all five content variants, structured data, independent metadata/extension levels and all resource bodies. Error state survives while runtime identity/control metadata remains protected.
- Non-object or duplicate arguments send nothing, including duplicate objects passed directly to execute through the checked client boundary. Valid success and remote RPC rejection become distinct Toolkit observations; an argument named name cannot reroute the binding.
- Invocation cancellation joins blocked cleanup and retains interruption and its cleanup defect. Existing client suites separately cover remote RPC code/data preservation before Toolkit's textual normalization.

[McpToolMetadataSpec](McpToolMetadataSpec.scala) checks actual registered ReAct calls expose the host-selected output schema through preset projection to both model calls without evaluating results, preserve the authorizer's rewritten input in history, apply missing defaults only to remote arguments, and retain restricted occurrence identity and separate host metadata; omission skips resolver effects while invocation-start snapshots, enabled empty objects and explicit client metadata remain distinct; typed resolver failure and invalid nested duplicates send nothing, while cancellation joins held cleanup and preserves its defect. The additional registered fixed-argument group checks preparation before approval, overlap with defaults, allowed nonfixed rewrites, exact history/provenance, metadata and remote arguments, denied fixed changes without a remote call, and empty raw fixed-only dispatch. The original defaults-only scenario remains intact. The manager suite checks custom-manager fallback and atomic rollback after malformed fixed selection.

[McpToolPresetsSpec](McpToolPresetsSpec.scala) checks shallow input-wins defaults, literal null/nested replacement and rejection of malformed original branches; root schema exclusion with preserved field order, absence, definitions, extensions and host flags. Checked fixed factories reuse this projection, leave defaults empty and reject malformed fixed values/original schemas. Empty policies and direct unprojected host bindings remain valid. Schema evaluation and reference rewriting are not tested or implemented.

These scenarios adapt fixed invocation, content conversion, explicit metadata propagation, preset merging and root schema exclusion from the pinned upstream methods recorded in the [parity audit](../../../../../../../../../../docs/architecture/test-parity.md#mcp-protocol-and-connection-boundaries). Omit is the metadata default; no generic runtime-context bag or mutable per-tool switch is introduced. Groups, caching, schema evaluation and provider multimodal support remain outside this scope. Existing client suites own transport/request/deadline coverage; resolver lifetime and timeout remain the invoking host's responsibility.

The host-definition fixture includes explicit provider schema strictness and asserts full definition equality after binding. The selected strictness contract is described in the [core strictness contract](../../../../../../../../../core/src/main/scala/com/weisgnosis/agents/core/tool/README.md#provider-tool-schema-strictness).

## Ordered metadata composition

[McpMetadataSpec](McpMetadataSpec.scala) uses one grouped table for ordered shallow replacement, literal null, empty sources, exact AST values and recursive duplicate rejection even in overwritten input. Existing McpToolMetadataSpec integration explicitly composes host defaults/live metadata and retains final runtime call-ID overlay, both omission gates and joined resolver cleanup.
