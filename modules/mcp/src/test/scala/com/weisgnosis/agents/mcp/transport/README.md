# com.weisgnosis.agents.mcp.transport: tests

The [supported server revision agreement](../../../../../../../main/scala/com/weisgnosis/agents/mcp/transport/README.md#supported-server-revision-agreement) adds opt-in checked revision membership, one scoped negotiation owner, atomic correlated initialization and immediate framing/header transitions. Exact-version defaults remain; legacy POST additionally carries the revision header. This does not establish complete original-plan parity.

The [immutable process launcher](../../../../../../../main/scala/com/weisgnosis/agents/mcp/transport/README.md#immutable-process-launcher) has actual subprocess fixtures. The stderr table checks exact reply correlation/content and reaping under discard pressure and native inheritance; the log marker is supplementary evidence, not an exact byte oracle. Actual process acquisition uses live System so inherited Windows key assertions do not depend on TestSystem.

The [current March batch contract](../../../../../../../main/scala/com/weisgnosis/agents/mcp/transport/README.md#march-2025-batch-packets) adds fragmented March stdio/JSON/SSE positives, JSON-specific June rejection/byte limits and shared packet November/June rejection, real subprocess grouped-response/reaping, controlled HTTP array POST replies and GET server batches, malformed response-prefix rejection, packet overflow, and singleton/grouped POST held-cleanup cancellation. Existing SDK checks remain singular and do not demonstrate batching. Batch-specific cursor replay remains unverified.

The paired suites verify the [framing, stdio and HTTP contracts](../../../../../../../main/scala/com/weisgnosis/agents/mcp/transport/README.md). Tests remain grouped by independent contracts without accessor tests or artificial count targets. The [legacy/revision contract](../../../../../../../main/scala/com/weisgnosis/agents/mcp/transport/README.md#legacy-http-sse-and-explicit-revision-selection) adds five controlled-port legacy groups, raw named-event framing and an unchanged SDK legacy servlet route. It also extends existing stdio coverage across three real-process handshakes and checks March-profile HTTP headers.

[McpStdioPeer](McpStdioPeer.scala) is a test-only ZIOAppDefault launched with the current JDK and forked MCP test runtime classpath. Its protocol messages report readiness, PID and the first consumed byte of a deliberately blocked write. Tests coordinate with these signals and fiber status, using live clock only for test deadlines; they contain no fixed sleeps or external Python/shell dependency.

Complete-cause fixtures use a direct ZChannel and check the unframed cause before framing, so stream construction cannot erase the mixed cause under test. Real-process fixtures do not induce OS permission failures or simulate process-tree containment; cleanup evidence is limited to their observed schedules.

The [resource client extension](../../../../../../../main/scala/com/weisgnosis/agents/mcp/client/README.md#resource-client-contract) extends the existing Java SDK loopback groups with resource discovery/read/template routes and typed list-change delivery.

## Acceptance and remaining tests

Run `sbt "mcp / test"` from the repository root for offline and owned local-process/loopback contracts. `sbt verify` also checks formatting and fatal-warning compilation. These tests do not establish interoperability with every server, complete protocol conformance or durable delivery.
