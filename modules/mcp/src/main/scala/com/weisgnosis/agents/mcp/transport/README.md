# com.weisgnosis.agents.mcp.transport

[McpTransport](McpTransport.scala) is a borrowed duplex message port. [McpStdioTransport](McpStdioTransport.scala) implements it for a host-selected direct child process; [McpStdioFraming](McpStdioFraming.scala) provides bounded UTF-8 newline framing. [McpHttpFraming](McpHttpFraming.scala) supplies bounded JSON/SSE bodies, and [McpStreamableHttpTransport](McpStreamableHttpTransport.scala) supplies the bounded HTTP POST and explicit GET contract below.

## Supported server revision agreement

The three built-in transport factories accept a trailing `supportedVersions: Option[McpSupportedVersions] = None`. `McpSupportedVersions.make` checks a nonempty immutable set; the preferred `version` must belong to it. Factories validate the entire set before acquiring processes or HTTP resources. Streamable HTTP excludes the pre-Streamable revision; legacy SSE retains all three existing profiles. Membership conveys neither preference ordering nor automatic probing, reconnection or replay. With None, initialization still requires the exact preferred revision.

`protocolVersion` is the preferred initial revision. `currentProtocolVersion` is an effect reading the committed wire revision. In opt-in mode, one scoped `McpProtocolLease` admits one connection before its reader starts. A rejected second owner cannot close the first connection. Raw users must explicitly acquire that lease before sending or consuming protocol input. Closing is idempotent and terminating: both connection shutdown and owner-scope release may invoke it. It completes owned cleanup and preserves failure causes, seals negotiation and retains the selected version; the host continues to own transport resources. Existing custom ports have exact-version/no-op-lease defaults. Wrappers must explicitly forward the new methods to preserve opt-in behavior.

The complete correlated singleton initialize result is validated before an atomic version transition. Malformed capabilities, unsupported versions, unrelated replies and batched initialize replies cannot commit a selection. Each subsequent frame uses the committed version, including another frame in the same input chunk. Thus selecting March enables its bounded batch framing immediately; selecting June rejects arrays immediately. This follows the [June lifecycle version negotiation contract](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle#version-negotiation).

HTTP encodings and headers share a coherent revision snapshot per outgoing request. Initialize POST responses and their same-send continuation GETs retain the initiating request identity; unsolicited listener GETs and unrelated POST replies cannot negotiate. Subsequent POST, listener GET, resumed GET and explicit DELETE use the selected revision. DELETE remains host-controlled after client lease closure. Legacy POST now also includes MCP-Protocol-Version, including in exact-default mode; unchanged default negotiation does not mean identical default wire output.

Legacy endpoint discovery is factory-owned: its initial GET must find the endpoint before the factory returns. After endpoint publication, protocol-frame consumption waits cancellably for the lease. Public unleased consumers fail before claiming the input queue. This setup GET is intentionally distinct from connection-owned protocol observation.

Migration: rebuild dependent binaries for appended factory parameters and additive transport methods. Existing source calls keep their defaults. No model/provider policy, tool authority, discovery refresh, durable execution or complete optional MCP-method conformance is introduced.

Controlled negotiation/header fixtures and real subprocess handshakes exercise different boundaries; packaged consumer probes do not establish negotiated interoperability with external servers.

## Immutable process launcher

The repository configures direct processes through zio-process 0.7.2's immutable Command API. System properties and inherited environment reads are suspended in ZIO; Windows overrides retain the inherited key spelling. Command.run executes on the blocking executor inside acquireRelease. Because that dependency's run is unscoped, our finalizer is registered before raw-handle extraction and ownership transfer. Failed or cancelled handoff forcibly terminates/reaps the acquired child and closes its streams; completed handoff uses the existing idempotent Live.close. No shell, streamed stdin, background pump or daemon is introduced.

Stdin/stdout explicitly use Pipe. Inherit selects native stderr inheritance; Discard redirects to the operating-system null device. The dependency internally uses JVM process machinery; this boundary does not claim immutable dependency internals. Application code neither obtains nor updates a mutable Java environment map. Public open arguments, default policies and direct-process ownership remain unchanged. Rebuild consumers to resolve the new production dependency.

Process fixtures check exact correlated replies and joined reaping under discarded stderr pressure and native inheritance. Inherited log markers are supplementary evidence, not exact byte oracles. Descendant-process containment, arbitrary stderr sinks and Linux execution are not established by the Windows process fixtures.

Dependency resolution selects ZIO/Streams 2.1.26 over zio-process's 2.0.9 and scala-collection-compat 2.14.0 over 2.9.0. sbt reports suspected binary incompatibility without an override or warning suppression. Process fixtures exercise these selected versions; they do not prove universal binary compatibility.

## March 2025 batch packets

The [March 2025 transport specification](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports) permits JSON-RPC arrays; the [June 2025 changelog](https://modelcontextprotocol.io/specification/2025-06-18/changelog) removes them. Batch support is selected by the committed protocol revision, not inferred from a successful handshake alone.

[McpPacket](../protocol/McpPacket.scala) preserves Single, nonempty Batch and the empty-array InvalidRequest case. A batch contains at most 64 members. Existing byte limits apply to the entire JSON body, SSE event or stdio line; one bounded incoming queue slot contains one complete packet. Complete parsing and direction validation precede publication, so an invalid response suffix cannot settle a valid prefix. Recursive duplicate keys reject the complete frame under the existing strict ambiguity policy.

Only selected 2025-03-26 accepts arrays. Default 2025-06-18 and selected 2024-11-05 retain singular framing. Server request/notification batches and response batches remain distinct; mixed-direction arrays and malformed response-shaped members terminate observation without sending response errors. Invalid request members yield -32600 with explicit id:null, grouped with valid request replies. An empty array yields one singular invalid-request error. Nested arrays are invalid request members. Notifications receive no reply; ping succeeds and unsupported methods receive -32601. Notification-only batches emit nothing. Initialization requests and their replies remain singular.

The connection's existing bounded control writer sends one response array per server request batch; it never flattens a group into independent POSTs or writes. Grouped response sends use independent control admission and own their response scope. Cancellation joins owned cleanup. No client-initiated multi-request batch API, request replay or automatic resource fetching is introduced. HTTP POST accepts a response array only when it contains the one response correlated to that singleton request; GET continues to reject RPC response packets. Packet admission precedes SSE cursor commit. Batch-specific cursor replay interoperability is not established by the existing singular continuation tests.

`McpTransport.incomingPackets` and `sendPacket` are additive. Existing custom ports default to Single packets and reject grouped sends atomically. Built-in transports provide packet streams; their original `incoming` view explicitly rejects batch packets and directs batch consumers to `incomingPackets`, preserving group semantics. Existing ordinary send calls and June defaults are unchanged. Consumers must rebuild for the additive JVM API. Grouped sends accept only server-request responses, never outbound client request batches.

Framing evidence is bounded: fragmented March arrays pass through stdio, JSON and SSE; the framing table rejects June arrays and an undersized byte budget on JSON. The shared McpPacket table rejects November/June arrays independently of framing. Separate stdio/SSE non-March rejection fixtures are not claimed. Existing framing suites retain their own singular byte-boundary and cleanup checks.

The pinned [Java SDK 0.17.2 McpSchema](https://github.com/modelcontextprotocol/java-sdk/blob/v0.17.2/mcp-core/src/main/java/io/modelcontextprotocol/spec/McpSchema.java#L188) `deserializeJsonRpcMessage` decodes a HashMap into three singular envelope records and leaves batching as a TODO; the AgentScope wrappers provide no batching method. Existing SDK interoperability therefore does not prove array support. Current batch fixtures derive from the official March transport and [JSON-RPC batch contract](https://www.jsonrpc.org/specification#batch), using controlled HTTP and a real direct subprocess.

## Legacy HTTP SSE and explicit revision selection

The scoped owner starts one GET reader, awaits a bounded initial `endpoint` event, and directs subsequent POST messages to the advertised URI. Server JSON-RPC arrives through `message` events; unnamed SSE events have the standard message meaning. Unknown named events are ignored, and a repeated endpoint is rejected. No reconnect, implicit redirect or POST replay is performed.

The advertised endpoint may be relative or absolute but must retain the configured scheme, host and effective port. Credentials and fragments are rejected. Host-supplied authentication headers therefore remain on the configured origin. The borrowed HTTP client must disable implicit redirects and retries; this adapter cannot undo network actions performed internally by a custom client. GET status/content type, UTF-8, cumulative body/event bytes and incoming queue capacity are checked. Overflow is terminal. Queue bounds count packets (singular messages under the legacy default) rather than decoded payload bytes; framing supplies the separate byte bounds. Every POST acknowledgement has an independent bounded response scope. Endpoint timeout/cancellation joins the reader response cleanup; send cancellation joins its response cleanup. The host must join its connection and active sends before closing the borrowed transport lifetime.

[McpProtocolVersion](../protocol/McpProtocolVersion.scala) supplies three initialized profiles. The legacy default is V20241105; stdio, Streamable HTTP and custom ports default to V20250618. Streamable HTTP also permits V20250326 and rejects V20241105. Exact-profile defaults reject alternatives; explicitly configured supported sets use the [server revision agreement contract](#supported-server-revision-agreement). No complete optional-method or ordered-preference parity is claimed.

Migration: the transport interface gains a default `protocolVersion` method, preserving existing custom implementers. `McpInitialization.request` and `readResult` append defaulted selection arguments; `McpInitializationResult` adds a trailing defaulted selected version. `McpStreamableHttpTransport.open` and `McpStdioTransport.open` append defaulted version arguments. Stdio supports each explicit initialized revision without HTTP headers; its existing real-process fixture verifies all three selected handshakes and reaps each child. Ordinary existing calls retain their defaults; positional patterns and dependent binaries require rebuilding.

Legacy/revision dependencies and current source destinations:

The paired [legacy transport suite](../../../../../../../test/scala/com/weisgnosis/agents/mcp/transport/McpLegacySseTransportSpec.scala) checks selected handshakes, safe/unsafe URI near-misses, held GET/POST cleanup and inbound violation/EOF/queue-exhaustion termination. Owned reader execution restores interruptibility inside masked acquisition; the initial new-feature run exposed the inherited-mask hang and was terminated rather than accepted. The SDK legacy servlet advertises only 2024-11-05; other selections have controlled-port evidence rather than an invented SDK compatibility claim. The existing framing suite checks named raw events without changing current Streamable message projection.

## Port and lifetime

The host acquires the transport before [McpConnection](../client/README.md) and releases it after connection cleanup. Incoming emits checked [McpMessage](../protocol/McpMessage.scala) values; outbound envelopes are checked before dispatch. Concurrent sends must not interleave frames. Real-world operations and resource acquisition remain suspended in ZIO.

Connection-owned callers join their I/O cleanup before transport release. Direct port users must keep consuming fibers inside the transport scope; the adapter does not own arbitrary escaped consumer fibers. Consumer code and finalizers must not close their own connection, which joins them.

A generic port may recover from a local send failure only if framing remains intact. Fatal or ambiguous writes must terminate incoming. The stdio implementation enforces the stricter entered-write policy below.

## Stdio contract

- `open(command, maxFrameBytes = 1048576, stderr = Discard, environment = Map.empty)` accepts a host-selected argument vector, rejects an empty/blank executable and nonpositive frame limit, and starts the process inside scoped blocking acquisition. It does not insert a shell. A shell explicitly supplied in the vector remains a host capability.
- `StderrPolicy.Discard | Inherit` redirects diagnostics separately from protocol stdout. No unread stderr pipe, log capture, or stdout merging is used. Working directory and environment are inherited; explicit [child-only environment overrides](#child-environment-overrides) replace selected child values.
- Incoming is single-use. A second consumer is rejected without acquiring the first consumer's release action. EOF, failure, cancellation or early consumption ends that reader and terminates the direct process. IO failures retain an operation label and exception class/message as typed McpError diagnostics.
- Outbound validation/encoding happens before write admission. One semaphore holds the complete frame write and flush. Cancelling a waiter for that permit does not poison the channel. Failure/interruption once writing is admitted publishes the first terminal cause before aborting, so subsequent pipe EOF cannot mask it. Later sends reject the terminated channel.
- Cancellation of native pipe I/O uses an explicit process termination action rather than relying on thread interruption. Cleanup force-terminates and waits for the direct child, then closes all three streams. Stream closes are attempted even when termination fails; concurrent cleanup callers share its complete outcome. Scope release also performs this cleanup.

This is direct-process ownership, not a process-tree sandbox. Descendant processes and inherited handles remain host/server responsibilities. The adapter has no graceful-shutdown timeout, reconnect policy, working-directory overrides, protocol initialization, request deadlines or self-originated cancellation notifications; it can carry the connection-owned notifications described below. A selected executable is trusted host configuration, not untrusted model output.

## Child environment overrides

The appended immutable environment map overrides selected inherited variables only in the direct child. Empty maps retain inheritance; empty values are preserved. Keys must be nonempty and contain neither equals signs nor NUL; values must not contain NUL. Override names that compare equal with String.equalsIgnoreCase are rejected on every platform, including Unicode case aliases. Windows updates the inherited key spelling; other platforms retain case-sensitive inherited names. This conservative override collision rule is portable admission policy, not a claim of identical native environment rules across operating systems.

Environment configuration uses the [immutable process launcher](#immutable-process-launcher); native implementation work is suspended before process start. Invalid override admission uses a static InvalidConfiguration message containing no supplied keys or values. The parent environment is never modified. Hosts select and protect environment values; these overrides grant no sandbox, secret storage, working-directory control or descendant-process ownership.

Migration: omitted/named Scala source calls retain their defaults. The appended parameter changes the JVM method signature and method-value arity; rebuild consumers and update explicitly typed function values. Existing send/read/cancellation/cleanup contracts are unchanged.

- Existing real-process groups now observe inherited PATH replacement, another retained inherited value, added/empty values, unchanged parent and joined reaping. Existing read/write cancellation coverage remains; no new group was added.

This bounded adaptation of pinned McpClientBuilderTest.testStdioTransport_WithEnvironmentVariables (74) does not implement the mutable builder, complete-wrapper assertions, automatic discovery caching or every platform/process configuration.

## Framing contract

The [selected stdio specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports) uses individual UTF-8 JSON-RPC messages separated by newlines. `decode(maxFrameBytes)` checks the retained raw bytes before appending a segment; completed frames use strict UTF-8 decoding and the checked envelope parser. LF is excluded from the bound; CR counts as a byte and is accepted as JSON whitespace in CRLF input. Empty/blank frames, BOM prefixes, malformed UTF-8/envelopes and nonempty unterminated EOF are rejected. Empty EOF is valid framing.

Split UTF-8 and multiple frames per chunk are supported. Completed messages are emitted individually; downstream early termination does not decode a malformed later frame or pull more input. Nonempty upstream causes pass through unchanged. Retained slices are copied so completed oversized input chunks are not pinned by their suffixes.

`encode(message, maxFrameBytes)` validates the envelope, produces compact JSON with a strict UTF-8 encoder, checks the exact byte length and appends one LF. Bounds count wire bytes, not total JVM memory or the size of an already constructed message/serialized string. The adapter reads bounded chunks of available data and waits for at least one byte rather than waiting for an entire frame-sized buffer.

## HTTP body framing

`McpHttpFraming.encode(message, maxBytes = 1048576)` produces checked compact UTF-8 JSON without a delimiter. `json(maxBytes = 1048576)` reads one complete checked envelope at EOF, rejecting empty, multiple-envelope, BOM-prefixed and malformed UTF-8 bodies. Positive limits are validated before input is pulled; the outbound limit is checked before and after UTF-8 encoding.

`sse(maxBodyBytes = 8L * 1024 * 1024, maxEventBytes = 1048576)` handles LF, CRLF and bare CR across chunk boundaries, strips one stream-leading BOM and combines `data` fields with newlines. Comments and other fields do not produce messages. A blank line dispatches a data event through the checked envelope decoder; `[DONE]` has no special meaning. Valid unfinished events are discarded at EOF, while an unfinished line must still contain valid UTF-8. Rejection of malformed UTF-8 is an explicit local policy, stricter than browser replacement decoding in the [SSE standard](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation).

`sseEvents` takes the same limits and emits the nested `McpHttpFraming.McpSseEvent(message: Option[McpMessage], lastEventId: String)` for every completed blank-line block. ID-only, comment-only and empty blocks have `message = None`; data blocks contain a checked envelope. Literal lowercase `id` fields replace the response-local cursor after removing at most one leading space. Missing IDs inherit within that response, the last valid field wins, an empty value or bare `id` resets to the empty string, and NUL-containing values are ignored. Unicode and remaining spaces are preserved. An unfinished EOF block emits neither a message nor a cursor snapshot. Each decoder run starts with an empty cursor.

The existing `sse` signature and message-only behavior remain compatible: it projects `Some(message)` from these snapshots. ID content counts toward the existing event/body bounds; complete causes and demand-preserving emission apply to both APIs. These snapshots do not install a network resume cursor or encode `Last-Event-ID` headers.

The body limit counts every consumed byte. The event limit counts raw line content, including comments, unknown fields and BOM bytes, excluding CR/LF separators; it resets at each blank line. CR dispatches immediately without waiting for optional LF. Retained segments are bounded before copying. Emitting one event precedes inspecting later bytes in the same chunk, so early downstream completion does not decode an unread suffix. Both decoders preserve complete upstream failure causes and join owned stream cleanup on cancellation. These bounds do not cap an already allocated upstream chunk or total JVM memory.

This component performs no HTTP requests, session negotiation, media-type dispatch, retries or cancellation notifications. It is a transport prerequisite, not an HTTP client or a complete protocol implementation.

## HTTP contract

`McpStreamableHttpTransport.open(http, endpoint, headers = Headers.empty, limits = McpHttpLimits(), continuation = McpHttpContinuation.Disabled)` returns `ZIO[Scope, AgentError, McpStreamableHttpTransport]` and borrows the injected zio-http Client. The acquired `McpStreamableHttpTransport` extends `McpTransport` with explicit `listen` and `terminateSession` operations. The absolute HTTP(S) endpoint cannot contain user information or a fragment. Header names must be ASCII tokens and values visible ASCII or spaces; transport-controlled headers cannot be overridden. Invalid configuration performs no network request.

Every message uses a separate POST with JSON content type, JSON/SSE Accept values and the selected protocol revision (`2025-06-18` by default). Requests accept one matching JSON reply or an SSE stream containing server requests/notifications before the matching reply. Matching completion closes the response scope without demanding an open tail. A premature SSE EOF fails the send unless bounded continuation is enabled below; a mismatched reply always fails it. Notifications and responses require exactly status 202 with an empty body. For JSON-RPC requests, response Content-Type must appear once and be JSON or SSE; only absent parameters or exact case-insensitive `charset=utf-8` / `charset="utf-8"` parameters are accepted. This parameter whitelist is a local compatibility constraint.

The first admitted initialize exchange can capture one nonempty visible-ASCII Mcp-Session-Id header before its SSE messages are delivered. Later POSTs carry that session ID; conflicting or malformed session headers terminate the transport. Duplicate initialize requests fail before sending, and rejected or queued-cancelled initializers cannot poison an existing session. Failure or cancellation after initialization admission terminates it, including response cleanup failures. Arbitrary stateless raw port requests remain possible; McpClient owns protocol initialization order, negotiated-version validation and capability checks.

HTTP 404 on POST, same-send continuation GET or explicit listener GET with a captured sent session fails with AgentError.McpSessionExpired() and terminates the old transport. The leaf carries only a fixed diagnostic and its individual codec is `{}`; no session token is exposed. The host must acquire a fresh transport and initialized client; the failed operation is never replayed automatically. A 404 without a captured session remains an ordinary McpError HTTP rejection; explicit DELETE retains its successful AlreadyExpired outcome. Expiry is distinct from JSON-RPC error replies and tool isError results. Only captured-session 404 is expiry; the pinned Java SDK's broader 400 handling is not adopted. Other request failures remain local unless they violate shared session state or overflow ingress. HTTP error bodies are not collected; status diagnostics remain explicit. Foreign network/body failures retain operation, exception class and message as McpError; existing AgentError values, full failure-cause structure and interruption are preserved.

Each send owns a fresh response scope and joins it before returning. Request admission has `maxConcurrentRequests` permits and control messages have a separate single permit, allowing a server ping response while ordinary requests are held open. The host HTTP pool must also permit this concurrency. Incoming is single-use; a rejected second consumer does not close the first. Bounded ingress uses immediate overflow failure rather than blocking producers. Terminal publication closes admission and discards queued messages, without joining its own producer. Owner closure and incoming completion perform local termination. The owning connection must join its send workers before transport release; escaped direct-caller fibers are not supervised by this adapter.

Default limits are 1,048,576 outbound JSON bytes, 1,048,576 JSON response bytes, 8,388,608 SSE response bytes, 1,048,576 SSE event-content bytes, 64 queued messages and eight concurrent requests. All must be positive. Framing bounds count consumed bytes; queue/admission bounds count entries. McpClient supplies joined operation deadlines; the raw port adds no timeout.

This is a bounded adaptation of the [2025-06-18 Streamable HTTP specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports). Recovery is limited to the explicit policies below and host-owned replacement after expiry. Legacy HTTP+SSE fallback, authentication discovery and token refresh are outside this adapter. Owner cleanup is local only. Only the opt-in continuation policies initiate additional GETs within a send; the borrowed host HTTP client must not add automatic retries or redirects. A bounded independent-server check is documented below; full transport conformance and broader interoperability remain unclaimed.

## Explicit GET listening

The host runs `listen: IO[AgentError, McpHttpListenResult]` or `listen(policy)` inside the transport lifetime, normally after `McpClient.open`. Neither starts automatically. Admission requires a matching initialize Success followed by a successful initialized notification POST and completion of that response's cleanup. This transport readiness check does not replace the client's version/result/capability validation. Early or duplicate listener attempts fail without terminating the active transport.

`McpHttpListenPolicy.Single` preserves no-argument behavior. `Resume(maxRestarts)` and the opt-in `ResumeOnBodyIoFailure(maxRestarts)` require positive budgets for additional GETs, validated before admission. One listener lease and action retain the originally captured session across all GET attempts; there is no daemon or fresh cursorless restart. Each response scope finishes cleanup before another GET. Resume permits clean EOF or the isolated typed closure failures described under [same-send continuation](#bounded-same-send-continuation); ResumeOnBodyIoFailure additionally permits the narrowly classified raw SSE body failure defined there. Both resume using the last successfully handled event's cursor. Zero completed snapshots retain the preceding cursor; a completed empty snapshot clears it. An unfinished block cannot advance it.

GET uses the configured endpoint/authentication, protocol version, captured session and SSE Accept header independently of POST request permits. `Last-Event-ID` is transport-controlled and uses the same checked UTF-8 header encoding as same-send continuation. Only server requests and notifications enter bounded ingress; every listener attempt rejects JSON-RPC responses, including resumed attempts. Existing strict SSE decoding, per-response body/event limits and immediate ingress-overflow failure apply.

Clean EOF with no committed cursor or no remaining restart budget returns `Ended`; HTTP 405 returns `Unsupported`. Both release admission after cleanup and leave POST usable. An eligible loss without a nonempty committed cursor or remaining budget preserves its original Cause. A cursor that fails header validation is rejected before another GET. Other I/O failures, protocol failures, mixed causes, cleanup failures and interruption do not restart; the eligible body classification is defined under same-send continuation. Caller interruption joins the action and cleanup before releasing admission; interruption alone is nonterminal. Other unhandled failures terminate the transport. A terminal signal interrupts and joins the complete listening action. The host must own and join it before transport release; no escaped caller supervision, session recovery or listening deadline is added.

Migration: the concrete `listen(policy)` overload is source-compatible for existing HTTP subtypes. Its default delegates `Single` to no-argument `listen`, rejects invalid budgets, and fails with a typed unsupported error for either resumable policy unless overridden. The additive enum case requires updating exhaustive matches. Existing no-argument callers are unchanged.

## Bounded same-send continuation

The final `open` parameter accepts `McpHttpContinuation.Disabled` (default), `OnPrematureEof(maxAttempts)`, `OnPrematureEofOrConnectionLoss(maxAttempts)` or the opt-in `OnPrematureEofOrBodyIoFailure(maxAttempts)`. All enabled policies require a positive shared GET-attempt budget, validated before acquisition. OnPrematureEof continues only after clean SSE EOF before the matching reply. OnPrematureEofOrConnectionLoss additionally recognizes direct typed `ClosedChannelException` (excluding `ClosedByInterruptException`) or `PrematureChannelClosureException` from SSE consumption or continuation GET acquisition. Existing policies retain these boundaries.

OnPrematureEofOrBodyIoFailure includes those existing cases and adds only an exact-class `java.io.IOException` with no cause from the raw SSE body stream before framing. ResumeOnBodyIoFailure uses the same additional body classification for the host-owned listener. This is an explicit policy choice: pinned zio-http can report both body timeout and premature closure as plain IOException, and a custom driver may report other I/O failures with that class. No message matching or cause-chain search occurs. IOException subclasses, cause-bearing wrappers, TLS and interruption subclasses are excluded from the new classification. It never widens request acquisition, JSON or acknowledgement bodies, HTTP status/session checks, framing, protocol or cleanup failures. Recovery still requires a singleton eligible typed failure after successful joined response cleanup; mixed causes, defects and interruption remain terminal.

The complete response scope must finish cleanup before another attempt. Cursor state is committed only after successful event handling; an unfinished block cannot advance it. Each continuation GET stays inside the original send, retaining its request ID, request-admission permit, client deadline and captured session. Matching initialization may capture its newly assigned session; unrelated concurrent initialization cannot change a raw request's session. No POST is replayed. Exhaustion preserves a classified failure; clean EOF exhaustion remains a protocol failure.

Migration: the new enum case is opt-in; existing policies retain their behavior. Exhaustive matches over McpHttpContinuation and McpHttpListenPolicy require the new cases; defaults remain unchanged.

Each response uses the existing byte limits and a fresh scope. A nonempty committed SSE cursor is required. A response producing zero completed snapshots retains the previous cursor; any completed snapshot replaces it with that response's cursor, including an empty reset. GET uses the configured endpoint/authentication, protocol version and captured session, accepts SSE only, and routes server requests/notifications until the original matching reply. Missing/reset cursors, exhausted attempts, unsupported responses and mismatched replies fail the original operation. Control responses retain separate admission. Listener resumption uses the separate `listen(policy)` contract above.

`Last-Event-ID` carries exact UTF-8 cursor bytes through the current zio-http/Netty byte-valued header representation; a loopback test checks the received bytes. To avoid invalid or normalized headers, continuation rejects DEL and C0 controls other than HTAB, plus leading/trailing SP or HTAB, under [RFC 9110 section 5.5](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.5). It neither trims nor percent-encodes IDs. Framing still preserves all valid Unicode ID data; not every preserved ID is usable as a continuation header. Host header overrides remain rejected.

This is a bounded adaptation of the [selected stream-specific replay contract](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports#resumability-and-redelivery), not general reconnect or exactly-once delivery. Existing callers keep disabled behavior unless the host opts in. Automatic cursorless reconnect, unowned subscriptions, in-place session mutation and POST replay are intentional exclusions. Hosts own bounded listening and any fresh client replacement after typed expiry; these exclusions are not promises of a further recovery API.

## Explicit session termination

The host calls `terminateSession: IO[AgentError, McpHttpTermination]` explicitly, normally after closing and joining its initialized client while retaining the transport scope. The first caller stops local admission and snapshots the session known at that instant; it does not wait for an in-flight initialize to assign one. Stopped transports retain their captured session so client closure does not prevent this operation. `NoSession` performs no network request but still leaves admission stopped.

With a captured session, one scoped DELETE uses the configured endpoint/authentication, protocol version and session header. Any 2xx status returns `Deleted`, 405 returns `Unsupported`, and 404 returns `AlreadyExpired`; other statuses fail. The response body is neither decoded nor drained, and response cleanup is joined. No retry, automatic reinitialization or background worker is introduced. Local admission remains stopped regardless of outcome.

Concurrent and later callers share the first attempt's complete `Exit`, published after cleanup. Cancelling the leading caller cancels and joins its attempt, including cleanup failures; cancelling a follower only stops that follower's wait. The transport owner finalizer never sends DELETE and seals an unclaimed attempt against later acquisition. A previously claimed outcome remains replayable after owner closure. Hosts must own and join termination, raw sends and listening within the transport lifetime; owner closure does not join arbitrarily escaped caller effects.

Migration: `terminateSession` is a new abstract member of `McpStreamableHttpTransport`. This is source-incompatible for custom implementations of that HTTP subtype, which must supply equivalent ownership and outcome semantics. The generic `McpTransport` interface is unchanged. Automatic owner cleanup remains local; explicit DELETE is an opt-in host action under the [selected session-management contract](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports#session-management).

## Cancellation publication boundary

`send(message, onIssued)` adds a bounded local publication callback to the borrowed port. Its default calls the original send and signals only on success, preserving existing implementers. Stdio overrides signal after a full validated frame write/flush. HTTP overrides signal after accepted status and validated session headers, before consuming the body. Pre-header interruption stays ineligible; this deliberately omits some optional notifications rather than treating local admission as a sent request.

[McpConnection](../client/README.md#outbound-cancellation-contract) originates bounded best-effort notifications under the [selected cancellation specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/utilities/cancellation), never for initialize. The transport does not originate notifications, and callback publication does not acknowledge peer delivery or stopping. HTTP cleanup can delay enqueue. The connection retains the notification writer independently of the cancelled request and joins it before transport release; no transport-wide guarantee orders notification delivery after all request finalizers.

## Independent-server interoperability

[McpJavaSdkInteropSpec](../../../../../../../test/scala/com/weisgnosis/agents/mcp/transport/McpJavaSdkInteropSpec.scala) runs the unchanged MCP Java SDK 0.17.2 HTTP servlet provider on Tomcat 11.0.18 over real loopback HTTP. The initialized Scala client verifies server information/capabilities, listing, successful text, tool `isError` and distinct RPC code/data.
