# Packaged public API consumer

This standalone, unpublished SBT fixture resolves core, harness, MCP and optional storage-postgresql and otel through generated Maven POMs and packaged JARs, without a source-project dependency. Only the declared staged Maven repository and Maven Central participate in resolution; implicit Ivy-local artifacts cannot substitute for the fresh packages. Archive admission also requires a licensed Scaladoc JAR with an index and a nonblank module POM description. Its neutral consumer package deliberately sits outside com.weisgnosis.agents and its package-private visibility boundary. It is external host verification infrastructure, not a published library component.

The default coordinates remain 0.1.1-SNAPSHOT. For an unsigned local candidate, select a canonical ASCII major.minor.patch-RCpositive version without leading zeros, at most 64 characters, for example 0.1.0-RC1. The root build checks -Dweisgnosis.candidate.version; the standalone build checks -Dweisgnosis.artifact.version. Neither selection creates a tag, frozen ABI or published release.

From the repository root, run sbt verify packageArtifacts for development artifacts, or sbt "-Dweisgnosis.candidate.version=0.1.0-RC1" verify packageArtifacts for a candidate. Then run `sbt "artifactVerification / runMain com.weisgnosis.agents.verification.CheckPreparation --version 0.1.0-RC1"` (omit `--version` for SNAPSHOT). In this fixture directory, run sbt "-Dweisgnosis.artifact.version=0.1.0-RC1" scalafmtCheckAll scalafmtSbtCheck clean compile run. On Windows use C:/tools/sbt/bin/sbt.bat. Root formatting does not format this standalone build.

[PrepareArtifacts](../artifact-preparation/src/main/scala/com/weisgnosis/agents/verification/PrepareArtifacts.scala), invoked with `sbt "artifactVerification / runMain com.weisgnosis.agents.verification.PrepareArtifacts --version 0.1.0-RC1"`, selects the same bounded version; --check-only validates the selector without filesystem mutation or artifact inspection. Ordinary preparation invalidates the old authorization manifest before selector/artifact failures. Inspection requires exact current Scala source entry names/counts and normalized source bytes, rejecting obsolete or duplicate Scala entries; it also checks all archive licenses, compiled class/TASTy presence, five POM coordinates/parent versions and fixture dependency scopes. Selected artifacts are staged under target/artifact-verification/repository with selected version and expected binary SHA-256 hashes in the manifest.

[CheckPreparation](../artifact-preparation/src/main/scala/com/weisgnosis/agents/verification/CheckPreparation.scala) uses reversible target-only source-JAR fixtures: a rejected selector must invalidate authorization, and extra/duplicate Scala entries must fail. Original archive bytes are restored by a scoped finalizer and the valid preparation is revalidated. It does not modify repository source files. These checks exercise archive admission, not published binary compatibility.

The forked consumer compares the selected version and hashes of five actually loaded module JARs against the fresh manifest. SNAPSHOT files may use Maven timestamp/build-number names; both exact and timestamped names require the same recorded SHA-256 hash. Runtime classpath inspection excludes source-project classes and known test/Java SDK/Tomcat/JDBC fixture dependencies. The standalone host selects slf4j-jdk14 at Runtime scope to provide logging; published library modules do not install a logging backend. Compile-time schema derivation also reads an enum from the packaged core dependency and executes its decoded High case, covering dependency TASTy metadata outside the source build. Jackson is a legitimate production transitive dependency of the private schema evaluator; the consumer executes valid/invalid schema-admission neighbors to verify that packaged path. It contacts no model provider or database; real PostgreSQL verification belongs to the configured backend suite.

The consumer restores and answers a typed user-question checkpoint, reopens an accepted procedure without repeating its executor, and checks the packaged Responses endpoint guard before network acquisition. Native Responses transport and cancellation are exercised separately by the core loopback/lifecycle specs.

The consumer repairs a schema-invalid final response through one output-only request after a local tool executes once, retaining its observation and rejected draft. It also executes a strict scripted tool/final turn, checks recorded next-request observations and rejects script exhaustion. It also checks explicit max_completion_tokens encoding, temperature omission with a configuration codec round-trip, and exact structured-output schema rejection followed by successful reuse of the same agent. It also exercises public external-tool suspension/resume, explicit typed-factory schema rejection/acceptance with exactly one handler invocation, full builder configuration with a thinking-retry override, representative request/settings and exact JSON contracts, MCP deadlines, permission precedence, explicit unavailable-channel denial and storage address/revision projection and explicit installation of the optional telemetry adapter with a host no-op tracer. It also exercises attributed sequential handoff, explicit truncated/Stopped completion and checked memory aggregate limits. It compares all five loaded module hashes. This is current-version source/packaging evidence, not exhaustive API coverage, binary compatibility, provider interoperability or publication.

## Candidate preparation acceptance

Candidate preparation checks package contents before authorizing the standalone run. Reversible negative archive fixtures verify rejected selectors and unexpected/duplicate Scala source entries, restore original bytes and revalidate the valid artifacts. The consumer then compiles from a clean standalone build and compares all five loaded module hashes. These checks establish selected current source/packaging behavior, not a frozen binary API or a published release.

The manual [candidate workflow](../../.github/workflows/candidate.yml) validates its version, provisions PostgreSQL 16, verifies/packages the selected modules, runs archive admission and the standalone consumer, and uploads unsigned artifacts/source metadata only after preceding steps succeed. Its optional operational boundaries are described in the [workflow guide](../../.github/workflows/README.md); remote CI is not a library completion requirement.

External publication is user-owned. The [single completion checklist](../../docs/architecture/tracker.md#remaining-library-completion-work) covers library behavior and local artifact verification.

The canonical repository is [weisgnosis/weisgnosis-agents](https://github.com/weisgnosis/weisgnosis-agents). Remote workflow execution, tags, signing, publication and frozen binary compatibility are not established by local artifact checks. The separately authorized [live smoke evidence](../../modules/examples/README.md#live-endpoint-verification) is bounded to the recorded endpoint run and is not executed by this consumer.
