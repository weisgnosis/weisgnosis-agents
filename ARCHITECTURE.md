# Architecture: weisgnosis-agents

## Runtime authority

[Terminal bindings](modules/harness/src/main/scala/com/weisgnosis/agents/harness/subagent/README.md#terminal-store-bindings) are explicit borrowed host capabilities. Catalog/session registries own execution and publication; they never infer partitions from names or acquire/close the supplied backend. This prerequisite restores observations, not executable session ownership, and does not install routed acknowledgement.

[Worker identity](modules/harness/src/main/scala/com/weisgnosis/agents/harness/subagent/README.md#worker-identity) is explicit host-declared descriptive data. It survives terminal storage and acknowledgement but grants no execution or delivery authority. The separate checklist governs final acceptance of schema-3 migration and reminder rendering.

The optional [accepted-response observer](modules/core/src/main/scala/com/weisgnosis/agents/core/agent/README.md#accepted-model-response-observation) sees winning request input and persisted accepted history before acting. The source-reviewed [local tool observer](modules/core/src/main/scala/com/weisgnosis/agents/core/agent/README.md#persisted-local-tool-observation) sees completed local dispatches after optional processing and final persistence, before completion events. Installed observers are required scoped effects: ordinary failure retains completed observations, reconciles unfinished local occurrences and preserves the cause. The terminal completion observer retains its distinct once-per-invocation contract. These ports do not themselves install task acknowledgement or durable conversation storage. The [bound task-result adapter](modules/harness/src/main/scala/com/weisgnosis/agents/harness/subagent/README.md#bound-task-inspection-consumption) connects trusted inspection and complete wait execution to unchanged persisted-result acknowledgement. [Local barriers](modules/harness/src/main/scala/com/weisgnosis/agents/harness/subagent/README.md#local-task-wait-barriers) retain a fixed selection and join task/publication observations without acquiring cancellation ownership. Explicit scoped inbox/session factories add a shared two-empty-timeout budget and latched host arrivals; arrival/no-work outcomes never grant acknowledgement. Final review gates remain explicit.

The explicitly configured [harness reminder adapter](modules/harness/src/main/scala/com/weisgnosis/agents/harness/subagent/README.md#automatic-reasoning-reminders) owns one bounded reminder capture, bounded task-result receipts and four configured scoped hooks. It persists the reminder before reasoning and acknowledges only captured IDs whose exact message appears in the winning request and accepted canonical history. It creates no daemon and grants no task execution authority.

The runtime owns state, cancellation, permission decisions, and completion. Model output is input to a deterministic state machine, never authority to bypass invariants. Pure transformations use immutable domain values. Randomness, clocks, filesystem access, network operations, and resource lifetimes belong inside ZIO effects.

ReActAgent retains in-memory history through private Ref values and serializes runs per instance. Data-only before-acting suspension, checked supplied results and explicit resume/restoration are implemented and independently reviewed. Partial-confirmation checkpoints are independently reviewed. Durable workflow replay, database transactions, authentication, and execution idempotency belong to the host.

## Core contracts

- Msg factories and codecs are pure. A private constructor, typed role factories, and validated dynamic updates make role/content checks unavoidable. The explicit identified effect allocates optional identity.
- Toolkit registration and merging return typed errors. Tools retain input/output types; failures become Error observations and cancellation propagates.
- AgentResult.state is Completed, Suspended, Interrupted or Stopped(reason). Host processor acting-stop decisions add ordinary Stopped results after the admitted batch drains; its reviewed contract distinguishes Stopped from suspended/resumable work. Suspended remains a domain capability, not installed durable middleware.
- LlmClient has scripted implementations and ChatCompletionsClient for scoped text/user-image/inline-audio/function HTTP completion. Explicit reasoning profiles preserve ordered assistant details and protected sibling arguments. Checked encrypted/text/summary objects preserve exact replay and matching plaintext events; other provider formats remain separate. Explicit bounded status retries reuse one logical request context and close every attempt before retry. Scoped model failover assigns a fresh target context after eligible pre-response rejection while retaining the prepared history and active request plan. Runtime-assigned ModelStreamContext correlates incremental model events; malformed or incomplete streams never dispatch tools.
- AgentEvent is a sealed hierarchy of 39 variants. Some variants belong to planned subsystems.
- Native structured output supplies LlmConfig.responseFormat; transports serialize it. Synthetic output uses generate_response and removes only synthetic context blocks.

## Context and permissions

Immediate eviction applies above 80,000 text characters with 2,000-character head/tail previews. Historical pruning uses a separate 2,000-character threshold when compaction is triggered. Safe boundaries preserve tool pairs; summary rebuilding retains raw-user provenance across coalescing for later memory flushing.

Permission gates combine with Deny > Ask > Passthrough > Allow. Unknown requests ask. Interactive requests use Promise; durable hosts serialize PendingApproval and later supply ConfirmResult. Decisions are not execution checkpoints or authenticated external approval tokens.

Filesystem protection requires canonical paths and a valid ownership contract. Local stores require explicit WorkspaceTrust.HostControlled and OS-protected ancestors. Tool-result publication requires hard-link support; daily-memory publication requires atomic-move support. Untrusted workspaces fail closed. Canonical checks alone do not provide an atomic sandbox against hostile directory replacement.

## Specifications and evidence

[AGENTS.md](AGENTS.md) owns canonical invariant IDs and engineering rules. The [tracker](docs/architecture/tracker.md) separates implemented contracts, tests, and pending integration. [High-level](docs/architecture/high-level-design.md), [mid-level](docs/architecture/mid-level-design.md), and [low-level](docs/architecture/low-level-design.md) documents describe current contracts and planned behavior. Source declarations remain authoritative for signatures.

Test counts do not establish exhaustive parity. Map each applicable upstream scenario and state pending or inapplicable cases explicitly in the [parity audit](docs/architecture/test-parity.md).

The typed AgentEvent API is the core event contract. Deprecated upstream v1 Event/EventType/EventSource envelopes are deliberately outside this port: no legacy filtering, cumulative snapshots, isLast field, or Java diagnostic compatibility is implied. The parity audit records all ten applicability decisions separately from behavioral evidence. Actual model streams now carry reply/request correlation; richer subagent attribution and remaining model/tool ordering are still required work.

Completed local and matched inline provider results can use a scoped ToolResultProcessor. The runtime stores raw completion before processing; cancellation preserves it, and successful payloads commit before model continuation/events. Harness ToolResultEvictor.processor installs immediate local/inline eviction. ConversationCompactor.preparer installs scoped preparation of canonical history before each model request; ToolResultEvictor.preparer installs supplied-history eviction. Core ToolAuthorizer now provides scoped per-call decisions before local execution, with precise approved-input persistence and fail-closed Denied observations. Its default explicitly allows calls; the harness interactive adapter is available through explicit installation. Durable resumption remains pending.

Absolute result storage is an opt-in ResultStorageLocation on ToolResultStore.local. It requires an existing host-controlled directory and protected ancestors outside the workspace; canonical location validation does not pin filesystem object identity.

ModelInputTransform provides a scoped request-only history view after canonical preparation. Structural validation precedes dispatch; projected values never replace canonical history, recovery positions, or invocation usage. Canonical eviction remains independent of pair omission from the model input.

Stored plan sessions now invalidate review before writing and reopen content only as unapproved Plan drafts. Opt-in model-facing controls are now available; descriptive location context is available; typed workspace-relative directories are available; durable approval restoration remains separate work.

PlanTools now adds strict opt-in enter/write/exit capabilities. Exact-ticket host review is mandatory inside exit even with ordinary Allow rules; publisher transport and authenticated decision routing remain host responsibilities.

PlanContext now associates one snapshot with configured/observed location metadata. Four additional manager/prompt scenarios and the stricter typed-directory scenario are adapted; no location value grants filesystem or approval authority.

Typed PlanDirectory configuration selects an existing strict descendant of an explicit host-controlled workspace. Native Path opening retains its semantics; no directory creation or implicit workspace discovery is provided. Opt-in Plan admission also consumes transient access from the actual admitted Tool while preserving explicit host classifications and live confirmation rechecks. Plan parity records fourteen bounded named adaptations, including explicit child-local installation and live inherited restrictions; literal Java APIs and durable approval restoration remain outside that scope.

The [versioned publication port](modules/harness/src/main/scala/com/weisgnosis/agents/harness/storage/README.md#versioned-json-publication) and optional PostgreSQL backend support explicit host-selected addresses. [Memory](modules/harness/src/main/scala/com/weisgnosis/agents/harness/memory/README.md#versioned-remote-memory) and [transcript](modules/harness/src/main/scala/com/weisgnosis/agents/harness/transcript/README.md#versioned-remote-transcript) adapters use bounded whole aggregates and retry only definite CAS conflicts. The [persistent memory trigger gate](modules/harness/src/main/scala/com/weisgnosis/agents/harness/memory/README.md#versioned-memory-trigger-gate) has final source/full/artifact verification; final combined documentation approval passed: it shares structural reservations over the same publication port and requires host-consistent policy/address and trusted synchronized clocks. Admission grants neither execution ownership nor completion. [Acting checkpoints](modules/harness/src/main/scala/com/weisgnosis/agents/harness/storage/README.md#versioned-acting-checkpoints) validate suspended data before one host-expected CAS without read-before-write or retry; source/full/artifact checks pass and final documentation approval passed. Hosts retain DataSource/schema ownership, runtime restoration gates, authentication, exclusive execution and replay/idempotency. The [immutable segment adapter](modules/harness/src/main/scala/com/weisgnosis/agents/harness/transcript/README.md#immutable-transcript-segments) has final source/full/artifact verification and final combined documentation approval, with a host-owned manifest/subtree and bounded complete-chain reads. The [explicit session catalog](modules/harness/src/main/scala/com/weisgnosis/agents/harness/transcript/README.md#explicit-transcript-session-catalog) has final source/full/artifact verification and combined documentation approval for discovery at one known host address; global discovery, automatic writer installation, orphan reclamation, compaction/pruning/layout migration and remaining provider/platform/release gates stay open. Package contracts and the tracker own exact review/verification evidence.
